### Q. 改名の取り残しで検証スクリプトが落ちたのはなぜか？
A. `git mv`（Git でのファイル移動・改名コマンド）の前に `Select-String`（PowerShell の文字列検索コマンドレット）で `docs/` フォルダと `AGENTS.md`・`CLAUDE.md` だけを検索し、ルートの `README.md` と `scripts/validate-agent-skills.ps1` を検索対象から取りこぼした。push 後に `validate-agent-skills.ps1` が `Missing required skill resource` というエラーで失敗して発覚した。`git grep`（Git 管理下の全ファイルを対象にした文字列検索）をリポジトリ全体にかけて3箇所を修正した。教訓として、`Select-String` でパスを列挙する方式は追跡対象の一部を取りこぼすため、改名の確認は `git grep` をリポジトリ全体にかけるところから始める、という方針にした。
（出典: 本日の作業から）

### Q. 規則8が半分しか機械化されていなかったとはどういう状態だったか？
A. 運用ガイドの規則8は「commit・push とリモートSHA（Git のコミットを一意に識別するハッシュ値）照合が終わるまで通常作業へ適用しない」ことを求めていたが、検証スクリプトの `-RequireGitTracked` スイッチはローカルの `HEAD`（現在のブランチが指す最新コミット）までしか確認しておらず、push する前の段階でも検査を通過してしまっていた。そのため毎回 `git rev-parse HEAD` と `git ls-remote origin main` を手作業で実行してリモートとの一致を確認していた。
（出典: 本日の作業から）

### Q. `-RequireRemoteSync` スイッチは何を検査するか？
A. 検証スクリプト `validate-agent-skills.ps1` に追加したスイッチで、現在のブランチの `HEAD` と origin（リモートリポジトリ）の完全SHAを比較し、不一致・リモート読み取り失敗・ブランチ不明のいずれの場合でも検査を失敗させる。`-RequireGitTracked` は `-RequireRemoteSync` を指定すると自動的に有効になる。既定の挙動（スイッチを指定しない場合の動作）は変更していない。検査が正しく働くことを、commit 後・push 前に落ちること（終了コード1）と、push 後に通ることを往復して確認した。
（出典: 本日の作業から）

### Q. PowerShell で `git show --stat --no-patch <SHA> | cat` がなぜ失敗するか？
A. PowerShell の `cat` は `Get-Content` コマンドレットのエイリアス（別名）であり、パイプ経由の標準入力を受け取れないため `InputObjectNotBound` エラーになる。加えて `--no-patch` オプションを付けると差分の統計情報自体も抑制されてしまう。解決策として `git --no-pager show --stat <SHA>` を使う方式に統一した。
（出典: 本日の作業から）

### Q. 複数行の文字列置換が `NOT FOUND` になったのはなぜか？
A. 引用ブロックが画面上は3行連続に見えたが、実際は空行が1行挟まって2つのブロックに分かれていた。`Get-Content`（PowerShell のファイル内容読み取りコマンドレット）の通常表示では空行の存在が見えにくいことが原因だった。解決策として `$i=0; Get-Content <path> | ForEach-Object { $i++; ... "[{1}]" -f $i,$_ }` のように各行を角括弧で囲んで表示し、空行の位置を確認したうえで行番号を指定して差し替えた。
（出典: 本日の作業から）

### Q. 日本語ファイルを BOM（Byte Order Mark、ファイル先頭に付くエンコーディング識別用のバイト列）無しの UTF-8 で書き換えるにはどうするか？
A. PowerShell 5.1 の `Set-Content -Encoding UTF8` は BOM を付加してしまい、日本語ファイル全体が差分として表示されてしまう。代わりに `[IO.File]::ReadAllText($p)` でファイル全体を読み込み、`.Replace('旧','新')` で置換したうえで `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding $false))` のように `UTF8Encoding` へ `$false` を渡してBOM無しで書き出す。置換が効いたかどうかは `if($t.Contains($old)){...; 'replaced'}else{'NOT FOUND'}` を末尾に付けて判定する。
（出典: 本日の作業から）

### Q. 番号付きリストの番号をずらすときに注意すべき点は何か？
A. 置換は番号の大きいほうから順にかける必要がある。先に小さい番号（例: 6→7）を実行すると、その結果を次の置換（例: 7→8）が拾ってしまい、同じ項目が二重にずれる不具合が起きる。
（出典: 本日の作業から）
