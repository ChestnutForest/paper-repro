### Q. 二点間比較と三点間比較の違いは何か？
A. `git diff A B`（ドット2つ、二点間比較）は2つの先端を直接比べるため、`A` にあって `B` に無いものも差分として並べる。`git diff A...B`（ドット3つ、三点間比較）は共通の祖先を起点にし、`B` が分岐後に加えた変更だけを出す。GitHub の Pull Request が使うのは後者である。PR #1 のブランチは `main` から145コミット遅れていたため、二点間比較では9月に `main` へ追加した文書が全部「削除」として出て、168ファイル・28,300行という数字になった。実際に変わるのは README.md 1ファイル、`+92 -28` だけだった。画面の `Files changed 1` が正しく、手元のコマンドの出力を画面と突き合わせずに結論へ使ったのが誤りだった。

### Q. Pull Request をマージせず閉じてよいかは、どう判定するか？
A. ブランチ独自のコミットが本当に不要かを確認する。`git log --oneline main..FETCH_HEAD` で `main` に無いコミットを列挙し、同じ内容が別のコミットとして `main` に入っていないかを `git log --all --grep` と `git diff <ブランチのSHA> <mainのSHA> -- <対象ファイル>` で調べる。`git diff` の出力が空なら両者のファイル内容は同一であり、閉じても失われない。PR #1 では `78a972e` と `bb2174e` が同じ README を持っていた。同じ変更が別経路で `main` へ入り、ブランチだけが取り残されていた。

### Q. Windows PowerShell 5.1 で `.ps1` の日本語が壊れるのはなぜか？
A. BOM のない UTF-8 ファイルを、既定のコードページ（日本語環境では932、Shift-JIS）として解釈するためである。日本語の各バイトが別の文字に化け、引用符が閉じられなくなって構文の解釈がずれる。PowerShell 7 は BOM なしを UTF-8 として読むため起きない。7 が未導入の場合、BOM を付ければ 5.1 でも正しく読める。ファイルの中身は1文字も変わらない。
（出典: 本日の作業から）

### Q. `docker info *> $null` が Docker 正常時に失敗するのはなぜか？
A. `*>` は標準エラーもリダイレクトする指定で、外部コマンドが stderr へ出力すると PowerShell 5.1 はそれを `NativeCommandError` という例外に変換するためである。`docker info` は WSL2 バックエンドで blkio throttle に関する警告を4件出すため、Docker が正常なほどこの判定は失敗しやすい。`try/catch` を外しても、`*>` を使う限り例外は出る。`cmd /c "docker info > nul 2>&1"` として stderr を cmd 側で処理すれば、終了コードだけが `$LASTEXITCODE` に入る。
（出典: 本日の作業から）

## 語彙・用語リスト（プロジェクト固有）
| 用語 | 定義 |
|---|---|
| 水準2 | 要件定義の完了をどこで区切るかの水準の1つ。文書間に矛盾がない状態を指す。水準1は初期リリースに必要な要件が揃っていること、水準3は未決事項がゼロであること |
| 上流工程 | 要件定義と、画面編・システム振る舞い編・データモデル編・外部インタフェース編の設計を指す。この間は既存の実装とテストの状態を判断材料にしない |
| 後工程 | 上流工程に続く工程。4編の設計、実装、テスト。要求項目を保留にするとき、担当工程としてこのいずれかを指定する |
| 保留の3項目 | 担当工程・解除条件・再判断の期限。これを欠いた保留は作らない |
| 静的な述語 | 「〜を提供するものとする」のように、成果物の名前と組にして振る舞いを表さない述語。USDM 第1.1節が書き直しの対象に挙げたもので、要求文へ書き戻さない |
| 二点間比較 / 三点間比較 | `git diff A B` と `git diff A...B`。前者は2つの先端を直接比べ、後者は共通の祖先を起点にする。GitHub の PR は後者を使う |
| コミット固定URL | `blob/<40桁のSHA>/<path>` の形式。`main` は次のコミットで内容が変わるため、変更した内容をその形のまま指すのはこの形式だけである |
