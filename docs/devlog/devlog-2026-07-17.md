## Q&A 知識カード

### Q. VS Codeで.envファイルを作るとき、なぜメモ帳を使ってはいけないか？
A. メモ帳で作るとファイルが「.env.txt」になってしまい、環境変数ファイルとして認識されないためである。VS Codeの統合ターミナルでコマンドを使うのが確実で、PowerShellなら「Copy-Item .env.example .env」で正しく.envを作れる。
（出典: 本日の作業から）

### Q. git add時に出る「LF will be replaced by CRLF」警告は対処が必要か？
A. 対処不要で、そのまま進めてよい。これはエラーではなくお知らせである。LF（ラインフィード、Mac/Linuxの改行コード）をCRLF（キャリッジリターン＋ラインフィード、Windowsの改行コード）に自動変換する予告であり、コードの中身は壊れない。警告を消したければ「git config --global core.autocrlf true」を実行する。
（出典: 本日の作業から）

### Q. git statusで.envが一覧に出ていないことを確認する理由は何か？
A. .envにはAPIキーなどの秘密情報を書き込むため、GitHubに上げると悪用される。このプロジェクトは.gitignoreで.envを除外設定済みなので、git statusで.env.example（テンプレート、秘密情報なし）は出てよいが、.env（秘密情報あり）は出ないのが正しい。コミット前にこの目視確認が最優先事項である。
（出典: 本日の作業から）

### Q. 既存コードをGitHubに初回pushする手順は何か？
A. (1) git init、(2) git branch -M main、(3) git add .、(4) git status で.env除外を確認、(5) git commit -m "説明"、(6) GitHubで空リポジトリを作成（README等はチェックしない）、(7) git remote add origin <URL>、(8) git push -u origin main、の順である。GitHubの空リポジトリはREADME等を追加しないことが重要で、追加すると初回pushが衝突する。
（出典: 本日の作業から）

### Q. 2回目以降にGitHubへ変更を反映する手順は何か？
A. (1) ファイルを編集、(2) Ctrl+Sで保存、(3) git add <ファイル名>、(4) git commit -m "説明"、(5) git push、の順である。初回のgit init・リポジトリ作成・認証・-u origin mainは済んでいるため、2回目以降はgit pushだけでよい。
（出典: 本日の作業から）

### Q. アプリUIの多言語化（i18n）の本質は何か？
A. i18n（internationalization、国際化）の本質は、コードに「作成」と直接書かず、t("create")のような鍵だけ書いておき、鍵と各言語の対応表を別ファイル（ja.json、en.json）に持たせることである。言語を切り替えると同じt("create")が「作成」やCreateに変わる。日本語をハードコード（直接埋め込み）しないことが要点である。
（出典: 本日の作業から）

### Q. i18nの仕込みを早い段階でやるべき理由は何か？
A. 画面を作り込んでから後で全文言を一括i18n化するのは大変なためである。画面を増やす前にライブラリ（Next.jsではnext-intl）を導入し、最初の画面からt("キー")方式で書いておけば、後から書き直す手間が消える。この方針をCLAUDE.mdに書いておくと、Claude Codeが最初からt方式で画面を書くようになる。
（出典: 本日の作業から）

## 語彙・用語リスト（プロジェクト固有）
| 用語 | 定義 |
|---|---|
| i18n（internationalization） | 国際化。画面文言をt("キー")方式にし、対応表を言語別ファイルに持たせて日英を切り替える仕組み |
| next-intl | Next.jsで多言語化を実現する定番ライブラリ。t("キー")で言語別の文言を出し分ける |
| ハードコード | コードに文言や値を直接埋め込むこと。i18nではこれを避け、鍵で参照する |
| LF／CRLF | 改行コード。LF＝Mac/Linux、CRLF＝Windows。Gitが自動変換の予告警告を出すことがある |
| .gitignore | Gitの管理から除外するファイルを指定する設定。.env（秘密情報）を除外している |
| git push -u origin main | ローカルのmainをGitHubのoriginに送り、以後の追跡先として設定するコマンド。初回のみ-uが必要 |
| Git Credential Manager | Gitに付属する認証ツール。PCからGitHubへアクセスする許可をブラウザ経由で得る |
