## 1. 調査の範囲と方法

先行分析（[`academic-research-skills.md`](academic-research-skills.md)）は大学3校の科目ページを一次資料としたが、**いずれも計算機科学以外の分野の科目**であり、機械学習論文の再現実装への適用には限界があった。そこで本書では、対象を次の2系統へ広げた。

| 系統 | 枠組み | 略号 |
|---|---|---|
| 学術スキルの一般的枠組み | SCONUL Seven Pillars of Information Literacy（Core Model と Research Lens） | REF-07 |
| 同上 | ACRL Framework for Information Literacy for Higher Education | REF-08 |
| 同上 | Vitae Researcher Development Framework（RDF） | REF-09 |
| 計算機科学・機械学習に固有の枠組み | ACM Artifact Review and Badging, Version 1.1 | REF-10 |
| 同上 | Pineau et al., Improving Reproducibility in Machine Learning Research (JMLR 2021) | REF-11 |
| 研究データと成果物の扱い | FAIR Guiding Principles (Wilkinson et al., 2016) | REF-12 |
| 貢献と責任の記録 | CRediT (Contributor Roles Taxonomy), ANSI/NISO 標準 | REF-13 |
| 研究公正 | ALLEA, The European Code of Conduct for Research Integrity, 2023年改訂版 | REF-14 |

**この2系統に分けたこと自体が本書の中心的な発見である。** 一般的枠組みは「情報をどう扱うか」を与えるが、`paper-repro` の核心である「論文の主張を自分の手で再現できたか」を判定する語彙を持たない。その語彙を持つのは計算機科学固有の枠組み（REF-10、REF-11）である。

## 2. 各枠組みの内容と、`paper-repro` への含意

### 2.1 SCONUL Seven Pillars（REF-07）

情報リテラシーを7本の柱で表す。**Identify（情報の必要性に気づく）→ Scope（現在の知識と欠落を評価する）→ Plan（探索の戦略を組む）→ Gather（入手する）→ Evaluate（過程を振り返り比較評価する）→ Manage（専門的かつ倫理的に整理する）→ Present（提示する）**。

重要な性質が2つある。

1. 各柱の内部で初心者から熟達者へ向かうが、**情報環境が変わるため柱を降りることもある**とされる。習熟は一方向ではない。
2. Core Model に対して利用者集団ごとの「レンズ」が用意されており、その第一号が **Research Lens**（研究者向け）で、Vitae RDF（REF-09）へ対応づけられている。

→ `paper-repro` の読解工程を、書籍由来の独自の順序ではなく、この7段階へ揃えられる。特に **Scope（自分の知識の欠落を先に評価する）** は、既存の読解順序（`PR-M-02`）に欠けている段階である。

### 2.2 ACRL Framework（REF-08）

6つのフレームで構成される。

| フレーム | `paper-repro` への含意 |
|---|---|
| Authority Is Constructed and Contextual（権威は構築され文脈依存である） | プレプリント・査読済み論文・ブログ・公式実装の重みは、用途によって変わる |
| Information Creation as a Process（情報の作成は過程である） | 同じ研究でも arXiv 版・会議版・拡張版で内容が異なる |
| Information Has Value（情報には価値がある） | ライセンス、権利、引用の帰属 |
| Research as Inquiry（探究としての研究） | 問いが次の問いを生む。読解は反復的 |
| Scholarship as Conversation（会話としての学術） | 論文は孤立した対象ではなく、先行・後続・反論の連鎖の一点 |
| Searching as Strategic Exploration（戦略的探索としての検索） | 検索は直線ではなく、反復と方向転換を含む |

### 2.3 Vitae RDF（REF-09）

研究者の能力を記述する枠組み。2010年版は**4ドメイン・12サブドメイン・63記述子**で構成され、各記述子が**3〜5のフェーズ（習熟段階）**を持つ。2025年改訂版では「Researcher」を中心の入口に据え、外周に「Research Communities」を置く構成へ変わり、知識交換・研究公正・オープンリサーチ・デジタルスキルなどの主題が更新された。**2010年版と2025年版が併存している点に注意が要る。**

→ 記述子ごとにフェーズを持つという設計は、`paper-repro` が**利用者の熟達段階に応じて支援の粒度を変える**根拠になる。

### 2.4 ACM Artifact Review and Badging v1.1（REF-10）

`paper-repro` にとって最も直接的な枠組み。**用語の定義が本製品の中核概念そのものである。**

| 用語 | 定義（v1.1） |
|---|---|
| Repeatability | 同じチーム・同じ実験設定。自分の計算を自分で再実行できる |
| **Reproducibility** | **異なるチーム・同じ実験設定。著者が提供した成果物を使って同じ結果を得る** |
| **Replicability** | **異なるチーム・異なる実験設定。著者の成果物を使わずに独立に開発した成果物で同じ結果を得る** |

**この2語の定義は、コミュニティによって逆に使われてきた歴史がある。** ACM は NISO の勧告を受けて用語を入れ替え、過去のバッジ表示も遡って統一したと明記している。したがって `paper-repro` は、**どちらの定義を採るかを製品として明示しなければ、利用者と食い違う。**

バッジは3系統。

- **Artifacts Evaluated** — Functional は「documented（成果物の目録と、実行できる程度の説明）」「consistent（論文に関連し主要結果の生成に寄与する）」「complete（関連する構成要素が可能な限り含まれる）」「exercisable（同梱のスクリプトが実際に実行でき、データを操作できる）」を満たすもの。Reusable はこれを大きく超え、再利用と転用が容易なもの。
- **Artifacts Available** — 恒久的に取得可能な公開アーカイブに置かれ、DOI または一意識別子つきのリンクがあるもの。**個人のウェブページは不可**と明記されている。
- **Results Validated** — Results Reproduced（著者の成果物を一部使って追試）と Results Replicated（著者の成果物を使わずに追試）。

さらに重要な一文がある。**厳密な一致は要求も期待もされず、その種の実験で許容される誤差の範囲で一致すればよい。ただし差が論文の主要な主張を変えてはならない。**

### 2.5 ML 再現性チェックリスト（REF-11）

機械学習分野で再現を妨げる3つの様式が整理されている。

1. **モデルや学習手順の記述が誤っているか不足している。** データやコードを公開しない場合でも、手順の全段階を明記すべきとされる。
2. **評価指標の定義が不十分である。** 指標を定義し、なぜその指標を選んだかを説明すべきとされる。
3. **結果が選択的に報告される。** 多数の試行のうち最良のものだけを示し、適切な評価を行わない。

チェックリストは、データセット、コード、ハイパーパラメータ、**学習と評価の実行回数**、指標の定義、**計算インフラ**の記載を求める。

### 2.6 FAIR 原則（REF-12）

15の原則からなる。`paper-repro` に効くのは主に次の点。

- **F1** (メタ)データに、globally unique で永続的な識別子を与える（DOI など）
- **F2** 豊かなメタデータで記述する
- **A2** データが失われた後もメタデータは残る
- **R1.1** 明確で参照可能な利用ライセンスとともに公開する
- **R1.2** 詳細な来歴（provenance）を伴わせる
- **R1.3** 分野の共同体標準を満たす

原則は機械可読性（machine-actionability）を重視しており、**人手を介さずに計算機が発見・取得・相互運用・再利用できること**を目標に置く。

### 2.7 CRediT（REF-13）

14の貢献役割からなる ANSI/NISO 標準。`paper-repro` に直結するのは **Software（プログラミング、実装、既存コードの試験）**、**Validation（結果や実験の複製・再現性の検証）**、**Data curation（メタデータの作成、データの整備と保守）**、**Methodology**、**Formal analysis**、**Project administration** である。貢献の程度を lead / equal / supporting で示せる。**CRediT は著者資格を決めるものではなく、貢献を記述するもの**と明記されている。

### 2.8 ALLEA 研究公正の行動規範（REF-14）

欧州委員会が EU 資金研究における第一の基準として認める規範。2023年改訂版は、データ管理の変化、GDPR、オープンサイエンス、研究評価の動向を反映している。

## 5. メイン項目

### ARF-M-01 読解工程を Seven Pillars の7段階へ揃える

- **根拠**: REF-07。Identify / Scope / Plan / Gather / Evaluate / Manage / Present の7柱と、研究者向けの Research Lens。
- **要求**: 論文1本の読解を7段階の工程として提示し、各段階の完了を記録する。段階は前後に行き来できる。
- **受入基準の案**: 利用者が段階を戻したとき、それを後退ではなく正常な経路として扱うこと。
- **サブ項目**
  - `ARF-S-01-1` **Scope 段階**として、読み始める前に「自分が既に知っていること」と「欠けていること」を明示させる。これは既存の読解順序（`PR-M-02`）に無い段階である。
  - `ARF-S-01-2` Plan 段階で、検索の戦略（データベース、検索語、絞り込み条件）を記録する。
  - `ARF-S-01-3` Evaluate 段階で、情報そのものだけでなく**探索の過程**も振り返らせる。
  - `ARF-S-01-4` Manage 段階に、倫理的な扱い（出典、権利）を含める。
  - `ARF-S-01-5` 段階を戻った履歴を保持し、どこで理解が崩れたかを後から辿れるようにする。
- **重複要確認**: `simclr-handson-deck.md` の `PR-M-02`（読解順序ナビゲーション）と統合するか、置き換えるかの判断が要る。

### ARF-M-02 再現の3水準（Repeatability / Reproducibility / Replicability）の明示と選択

- **根拠**: REF-10。3語が異なる実験条件を指し、ACM は NISO の勧告により Reproducibility と Replicability の定義を入れ替えた経緯を明記している。
- **要求**: 利用者が今回の再現で目指す水準を選べるようにし、水準ごとに必要な手順と成功条件を変える。製品が採用する定義を明示する。
- **受入基準の案**: 成果物のどこにも「再現できた」という語を、水準を伴わずに単独で書かない。
- **サブ項目**
  - `ARF-S-02-1` 著者提供の成果物（公式実装、重み、データ）を**使うか使わないか**を最初に選ばせ、選択に応じて水準を決める。
  - `ARF-S-02-2` 採用した定義がどの規格に基づくか（ACM v1.1）を成果物に明記する。
  - `ARF-S-02-3` 逆の定義を使う文献を読むときのために、用語の対照を提示する。
  - `ARF-S-02-4` 公式実装が存在するかどうかの調査結果を、水準の判断材料として保持する。
- **これは `paper-repro` の中核概念そのものであり、最優先で5択へ進めるべき項目である。**

### ARF-M-03 成果物の品質を4基準で自己点検する

- **根拠**: REF-10 の Artifacts Evaluated – Functional の4基準。documented（目録と実行できる程度の説明）、consistent（論文に関連し主要結果の生成に寄与する）、complete（関連する構成要素が可能な限り含まれる）、exercisable（同梱のスクリプトが実際に実行でき、データを操作できる）。
- **要求**: 再現実装の成果物が4基準を満たすかを点検し、不足を列挙する。満たした場合に相当するバッジ水準（Functional / Reusable）を示す。
- **受入基準の案**: exercisable の判定は、**まっさらな環境で実際に実行して**行う。利用者の手元で動いたことをもって満たしたとしない。
- **サブ項目**
  - `ARF-S-03-1` 成果物の目録（inventory）を自動生成する。
  - `ARF-S-03-2` 入手できない専有データがある場合、その旨と入手手順、および代替データを明記する。
  - `ARF-S-03-3` 再利用と転用を容易にする水準（Reusable）を目指すかどうかを選べる。
  - `ARF-S-03-4` 分野の慣行に従っているかを点検項目に含める。
  - `ARF-S-03-5` 点検結果を、成果物に同梱できる形式で出力する。

### ARF-M-04 再現に必要な情報の充足検査

- **根拠**: REF-11 が求める記載項目（データセット、コード、ハイパーパラメータ、学習と評価の実行回数、指標の定義、計算インフラ）と、記述の不足という失敗様式。
- **要求**: 論文からこれらの項目が取得できたかを検査し、欠落を一覧にする。欠落は推測で補わず、**仮定台帳へ送る**。
- **受入基準の案**: 検査結果に「取得済み」「論文に記載なし」「未確認」の3状態を持たせ、2値にしない。
- **サブ項目**
  - `ARF-S-04-1` ハイパーパラメータを、論文本文・付録・公式実装のどこから得たかを出典つきで記録する。
  - `ARF-S-04-2` 計算インフラ（GPU種別、台数、学習時間）の記載を抽出する。
  - `ARF-S-04-3` 前処理の手順を、モデル構造とは別項目として抽出する。
  - `ARF-S-04-4` 欠落項目を、`simclr-handson-deck.md` の `PR-M-08`（差分Δと仮定台帳）へ引き渡す。
  - `ARF-S-04-5` 論文に記載がなく公式実装にのみある値を、「論文外由来」と区別して保持する。

### ARF-M-05 評価指標の定義と選定理由の抽出

- **根拠**: REF-11 の失敗様式2。指標を定義し、選定理由を説明すべきとされる。
- **要求**: 論文が用いる評価指標を、定義・計算方法・選定理由とともに抽出する。
- **サブ項目**
  - `ARF-S-05-1` 同名でも定義が異なりうる指標（accuracy の集計単位など）について、論文の定義を優先する。
  - `ARF-S-05-2` 指標の変種（Top-1 と Top-5 など）を区別して保持する。
  - `ARF-S-05-3` 選定理由が論文に書かれていない場合、「理由の記載なし」と明示する。
  - `ARF-S-05-4` 再現時に別の指標を使う場合、置換を差分Δとして記録する。

### ARF-M-06 実行回数と分散の記録（選択的報告の抑止）

- **根拠**: REF-11 の失敗様式3。多数の試行のうち最良のものだけを報告する慣行が指摘されている。
- **要求**: 再現実行について、乱数種、試行回数、各試行の結果、要約統計を記録する。単一実行の結果は「単一実行」と明示する。
- **受入基準の案**: 成果物に載せる数値には、必ず試行回数を併記する。
- **サブ項目**
  - `ARF-S-06-1` 乱数種を記録し、同じ種で再実行できるようにする（Repeatability の担保）。
  - `ARF-S-06-2` 失敗した試行、途中で止めた試行も記録に残す。
  - `ARF-S-06-3` 最良値だけを取り出す操作に対して注意を出す。
  - `ARF-S-06-4` 論文側の試行回数の記載有無を、`ARF-M-04` の検査項目に含める。
- **本書で最も新規性が高い項目である。** 既存のどの一次資料にも対応する要求がない。

### ARF-M-07 成果物のFAIR化（識別子・メタデータ・ライセンス・来歴）

- **根拠**: REF-12 の F1・F2・A2・R1.1・R1.2・R1.3。および REF-10 の Artifacts Available（恒久アーカイブ、DOIまたは一意識別子、**個人ウェブページは不可**）。
- **要求**: 再現の成果物に、永続識別子、機械可読なメタデータ、明示的なライセンス、来歴を付与し、恒久アーカイブへ登録できる形に整える。
- **受入基準の案**: ライセンスが不明な構成要素を含んだまま公開手順へ進ませない。
- **サブ項目**
  - `ARF-S-07-1` 成果物へ永続識別子（DOI 等）を付与する手順を案内する。
  - `ARF-S-07-2` メタデータを機械可読な形式で出力する。
  - `ARF-S-07-3` 元論文、公式実装、データセットそれぞれのライセンスを記録し、成果物のライセンスとの整合を点検する。
  - `ARF-S-07-4` 来歴（どのデータをどう加工し、どの設定で何を得たか）を連鎖として記録する。
  - `ARF-S-07-5` 保存先として個人のウェブページを選ばせない。
  - `ARF-S-07-6` データが失われてもメタデータだけは残る構成にする。
- **先行分析の `AR-M-01`（引用と参考文献の管理）を包含する。** 統合するか併存させるかは要判断。

### ARF-M-08 貢献の記録（CRediT 準拠）と、人間・生成AIの寄与の切り分け

- **根拠**: REF-13 の14役割。特に Software、Validation、Data curation、Methodology、Formal analysis、Project administration。CRediT は著者資格を決めるものではないと明記されている。
- **要求**: 再現プロジェクトにおける貢献を CRediT の役割語彙で記録し、生成AIが担った部分を人間の貢献と区別して残す。
- **受入基準の案**: 生成AIを著者・貢献者として登録できないようにする。あくまで使用の記録として扱う。
- **サブ項目**
  - `ARF-S-08-1` 役割ごとに lead / equal / supporting の程度を記録する。
  - `ARF-S-08-2` 生成AIの利用箇所、モデル名、日付を記録する。
  - `ARF-S-08-3` Validation（再現性の検証）を独立した役割として明示する。
  - `ARF-S-08-4` 記録を、成果物に添付できる定型で出力する。

### ARF-M-09 出典の権威性を文脈依存で評価する

- **根拠**: REF-08 の Authority Is Constructed and Contextual。権威は共同体によって構築され、情報の用途によって必要な権威の水準が変わる。
- **要求**: 参照する資料を、種別（プレプリント、査読済み、公式実装、第三者実装、ブログ、生成AI出力）で分類し、用途ごとに許容する種別を設定できるようにする。
- **サブ項目**
  - `ARF-S-09-1` 同一研究の arXiv 版と会議版の差異を記録する（REF-08 の Information Creation as a Process）。
  - `ARF-S-09-2` 主要な数値の根拠には査読済み版を優先する、といった規則を設定できる。
  - `ARF-S-09-3` 公式実装と第三者実装を区別し、混同させない。
  - `ARF-S-09-4` 生成AIの出力を、それ単独では根拠として採らない。

### ARF-M-10 論文を学術的会話の一点として位置づける

- **根拠**: REF-08 の Scholarship as Conversation および Research as Inquiry。
- **要求**: 対象論文を、先行研究・後続研究・反論・追試の連鎖の一点として提示する。
- **サブ項目**
  - `ARF-S-10-1` 追試や再現失敗の報告を、後続研究と同じ重みで扱う。
  - `ARF-S-10-2` 論文への反論・批判を、賛同する引用と区別して収集する。
  - `ARF-S-10-3` 読解の過程で生じた新しい問いを記録し、次に読む論文の候補にする。
- **重複要確認**: `PR-M-04`（歴史的文脈）、`PR-M-12`（限界と後続研究マップ）と重なる。本書の追加分は「**追試と反論を対等に扱う**」点である。

### ARF-M-11 検索を戦略的探索として記録する

- **根拠**: REF-08 の Searching as Strategic Exploration。REF-07 の Plan と Gather。
- **要求**: 検索の条件、実行日、結果件数、採用・除外した資料とその理由を記録する。
- **サブ項目**
  - `ARF-S-11-1` 検索式と対象データベースを再実行可能な形で保存する。
  - `ARF-S-11-2` 除外した資料を、理由つきで残す（再検討の手間を省くため）。
  - `ARF-S-11-3` 検索を実行した日を記録する（結果は時間とともに変わるため）。

### ARF-M-12 熟達段階に応じた支援の粒度調整

- **根拠**: REF-09。63の記述子がそれぞれ3〜5のフェーズを持ち、習熟段階を区別する設計になっている。REF-07 も柱ごとに初心者から熟達者への移行を想定し、かつ後退もありうるとする。
- **要求**: 利用者の熟達段階を領域ごとに保持し、支援の粒度（手順の細かさ、前提知識の説明量）を変える。
- **サブ項目**
  - `ARF-S-12-1` 熟達段階を単一の値ではなく、領域ごとに分けて持つ。
  - `ARF-S-12-2` 段階の低下も記録できるようにする（分野を移ったときなど）。
  - `ARF-S-12-3` 段階の自己申告と、実際の作業記録から推定される段階の両方を保持する。
- **重複要確認**: `simclr-handson-deck.md` の `PR-M-14`（前提知識ギャップの検出）の上位概念にあたる。

### ARF-M-13 研究公正の行動規範への適合点検

- **根拠**: REF-14。欧州委員会が EU 資金研究の第一基準として認める規範であり、2023年改訂でデータ管理・GDPR・オープンサイエンス・研究評価の動向を反映している。
- **要求**: 成果物を公開・共有する前に、行動規範の観点（出典の明示、データの扱い、個人情報、権利）から点検する。
- **サブ項目**
  - `ARF-S-13-1` 個人情報や機微データを含む場合に警告する。
  - `ARF-S-13-2` 準拠する規範とその版を、利用者が選べるようにする（分野・地域で異なるため）。
  - `ARF-S-13-3` 点検を通過していない成果物を、公開手順へ進ませない。
- **先行分析の `AR-M-02`（研究倫理とインテグリティ）を、具体的な準拠先とともに置き換える。**
