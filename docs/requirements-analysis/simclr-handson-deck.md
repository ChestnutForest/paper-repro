## 4. メイン項目の詳細

### PR-M-01 書誌・出所カードの自動生成

- **根拠**: 「論文概要」スライドが、著者・タイトル・会議名・年・ページ・DOI・引用数（2026/03/08時点）を定型で並べている。「私の論文の読み方」でも Title → 著者（所属）を最初に確認するとしている。
- **要求**: 論文のURLまたはPDFを入力すると、書誌情報を構造化カードとして提示する。
- **受入基準の案**: 取得できなかった項目は推測せず null とし、画面上も「未取得」と表示する。引用数など時間とともに変わる値は、必ず取得時点を併記する。
- **サブ項目**
  - `PR-S-01-1` 著者の所属（研究室・企業）を抽出し、どの組織の研究かを判別できるようにする。
  - `PR-S-01-2` 引用数は取得日時とセットで保存し、再表示時に「◯◯時点」と表示する。
  - `PR-S-01-3` DOI と arXiv ID を相互に解決し、恒久リンクを保持する。
- **重複要確認**: 書籍「1.2 論文を読み解く技術」由来の書誌抽出要求と重複する可能性が高い。

### PR-M-02 読解順序ナビゲーション

- **根拠**: 「私の論文の読み方」の Title → 著者（所属）→ Abstract → 図表 → Supporting Information（SI）という順序。化学系論文では Method が本文になく SI を見る必要があるとしている。
- **要求**: 読解の順序を工程として提示し、各ステップの完了状態を記録する。分野に応じて順序プリセットを切り替えられる。
- **サブ項目**
  - `PR-S-02-1` SI・Appendix・補足資料を本体PDFと紐づけて同一プロジェクトに取り込む。
  - `PR-S-02-2` 分野別プリセット（例: 化学系は SI を必読ステップに含める）を選択できる。
  - `PR-S-02-3` 本文を読む前に図表ステップへ進める「図表優先モード」を用意する。
  - `PR-S-02-4` 途中で中断しても、どのステップまで進んだかを復帰時に復元する。
- **重複要確認**: 書籍のスリーパス法（読む価値の判断→仕様抽出）と役割が重なるため、統合するか併存させるかの判断が必要。

### PR-M-03 図表ファーストの抽出と要点化

- **根拠**: 「図表に情報が集約されているはず、まず最初に理解しにいく」。実際に本PDFの解説の中心は Figure 1（線形評価の比較）、Figure 7（モデル規模）、Figure 8（Projection Head の次元と種類）、Table 7（少量ラベル）である。
- **要求**: PDFから Figure・Table を、画像・キャプション原文・本文中の言及箇所とともに抽出し、図表単位の要点カードを生成する。
- **受入基準の案**: 図表番号（Figure 8、Table 7 など）を保持し、要点カードから原図へ1クリックで戻れる。
- **サブ項目**
  - `PR-S-03-1` キャプション原文を改変せずに保持する。
  - `PR-S-03-2` 図中の数値をグラフから目視で読み取った場合は「読み取り値」と明示し、本文記載値と区別する。
  - `PR-S-03-3` ヒートマップ・棒グラフなど図の種類に応じて、読み取るべき観点（対角/非対角、系列間の大小）を提示する。
  - `PR-S-03-4` 図表ごとに「この図が主張していること」を1文で要約する。

### PR-M-04 歴史的文脈と従来手法との対比の生成

- **根拠**: 「歴史的背景/当時の状況（2020年初頭のAI界隈）」が、Transformer（2017）、BERT（2018）、ResNet、投稿の数ヶ月後の ViT を時系列で並べている。「イントロ/手法の変遷: 生成から識別へ」が、生成アプローチ（オートエンコーダ、GAN）と識別アプローチ（対照学習）を左右に対比している。
- **要求**: 対象論文の前後の関連研究を年表として提示し、あわせて「従来手法 vs 提案手法」の対比表を生成する。
- **サブ項目**
  - `PR-S-04-1` 論文の投稿日・公開日と、後続研究の発表日の前後関係を明示する。
  - `PR-S-04-2` 分野をまたぐ影響関係（NLPの自己教師あり学習が画像分野へ波及）を記述できる。
  - `PR-S-04-3` 従来手法の課題（ピクセル復元は計算が重く、分類に不要な細部まで学習する）を、提案手法の設計動機と1対1で対応づける。
  - `PR-S-04-4` 同じ役割の要素が、従来と提案でどう役割を変えたかを記述する（データ拡張は正則化の手段から、予測タスクそのものの定義へ）。

### PR-M-05 手法の構成要素分解（記号・役割・次元）

- **根拠**: Base Encoder f(·) は特徴抽出で出力は表現 h、ResNet-50 なら2048次元、ResNet-18 なら512次元。Projection Head g(·) は表現 h をベクトル z へ変換し、構造は Linear → BatchNorm → ReLU → Linear の2層MLP。
- **要求**: 論文中の記号を一覧化し、各コンポーネントの入力・出力・形状・役割・学習後の扱いを表にする。
- **受入基準の案**: 記号表の各行に、論文中の出現箇所（節・図番号）を出典として紐づける。
- **サブ項目**
  - `PR-S-05-1` 記号表（f, g, h, z, τ, N など）を生成し、同じ記号が別の意味で使われていないかを検査する。
  - `PR-S-05-2` 次元数がバックボーン依存で変わる箇所を明示する（2048次元 / 512次元）。
  - `PR-S-05-3` 層構成を、実装のレイヤ列（Linear → BatchNorm → ReLU → Linear）としてそのまま出力する。
  - `PR-S-05-4` 学習後に破棄されるコンポーネント（Projection Head）を「破棄」と明示し、下流タスクで使う表現がどれかを取り違えないようにする。

### PR-M-06 目的関数の定式化抽出と実装マッピング

- **根拠**: NT-Xent Loss（Normalized Temperature-scaled Cross Entropy）の式と、「バッチサイズ256 → 正例1ペア、負例510サンプル」という具体的な数え方。
- **要求**: 損失関数の数式を抽出し、実装に必要な要素（類似度、温度パラメータ、自己を除くマスク、2N構成）へ分解する。バッチサイズを入力すると正例・負例の数を自動計算する。
- **サブ項目**
  - `PR-S-06-1` 総和の範囲（2N）と、自己を除く指示関数の扱いを、実装上のマスク処理として明示する。
  - `PR-S-06-2` 温度パラメータ τ の既定値と、論文中で探索された範囲を抽出する。
  - `PR-S-06-3` バッチサイズから正例数・負例数を計算して表示する（256 → 正例1ペア、負例510）。
  - `PR-S-06-4` 数値安定性（対数・指数計算）の実装上の注意点を注記する。

### PR-M-07 アブレーション読み解きによる必須要素判定

- **根拠**: Crop と Color の組み合わせのヒートマップ。Crop のみではショートカット解（色分布などの低次統計量に依存した識別）が起き、意味的表現の獲得が阻害される。Projection Head は None / Linear / Non-linear の比較で、32次元の非線形が Head なしの2048次元を上回る。
- **要求**: 論文のアブレーション結果から「省略できない要素」と「省略できる要素」を切り分け、再現実装の必須リストと任意リストを生成する。
- **受入基準の案**: 必須と判定した各要素に、根拠となる図表番号と数値を添える。
- **サブ項目**
  - `PR-S-07-1` 単独では効果が小さいが組み合わせで効く要素（Crop＋Color）を、組み合わせ効果として検出する。
  - `PR-S-07-2` ショートカット解が起きうる設定を警告として提示する。
  - `PR-S-07-3` 「必須」と判定した要素を、後段の実装チェックリストへ自動的に引き継ぐ。
  - `PR-S-07-4` 論文が明示的に否定した選択肢（Projection Head なし、線形のみ）を、実装時の誤りとして検出できるようにする。

### PR-M-08 スケールダウン・プランナー（差分Δと仮定台帳）

- **根拠**: 論文はバッチサイズ最大8192、ResNet-50、ImageNet、LARS オプティマイザ。一方でハンズオンは Colab の計算資源制約を考慮し、バッチサイズ256＋AdamW、ResNet-18、STL-10 を採用し、LARS の実装コードは参考として Notebook 内に収録している。さらに「バッチサイズが小さい場合でも、十分な学習時間（例: 1000 Epoch）を確保することで大規模バッチ設定に近い性能へ到達可能」という補償関係も示されている。
- **要求**: 利用可能な計算資源（GPU種別、メモリ、実行時間の上限）を入力すると、「論文設定 → 再現設定」の対応表を生成する。各行に、変更点・変更理由・期待される性能差・出典を持たせる。
- **受入基準の案**: 変更した設定は1件も暗黙にせず、すべて差分Δとして表に残す。性能差の見込みを断定できない場合は「不明」と書き、推測値を書かない。
- **サブ項目**
  - `PR-S-08-1` データセットの代替（ImageNet → STL-10）を提示し、ラベルなし約100,000枚・ラベルあり5,000枚という規模の違いを明示する。
  - `PR-S-08-2` バックボーンの代替（ResNet-50 → ResNet-18）に伴う表現次元の変化（2048 → 512）を自動で追随させる。
  - `PR-S-08-3` オプティマイザの代替（LARS → AdamW＋勾配クリッピング）を提示し、置換の理由と副作用を記述する。
  - `PR-S-08-4` バッチサイズ縮小を学習エポック延長で補償する案を、計算コストとのトレードオフとともに提示する。
  - `PR-S-08-5` 採用しなかった論文どおりの実装（LARS 実装コード）を、参考として成果物内に残す。
  - `PR-S-08-6` 差分Δの各行を仮定台帳へ転記し、再現結果が論文と食い違ったときの原因候補として参照できるようにする。

### PR-M-09 再現スコープ定義書の生成

- **根拠**: 「ハンズオン/SimCLRの主要構成要素」が、実装対象を(1)データ拡張、(2)エンコーダおよび投影ヘッド、(3)対照学習損失関数、(4)獲得表現の評価、の4点に絞り込み、使用データセットを明記している。
- **要求**: 論文から「今回再現する要素」を4〜6個に絞ったスコープ定義書を生成する。データセット、モデル、損失、評価の4区分を必ず含む。
- **サブ項目**
  - `PR-S-09-1` スコープ外とした要素を、除外理由つきで明記する。
  - `PR-S-09-2` 各構成要素に、実装の完了判定条件（サニティチェック）を紐づける。
  - `PR-S-09-3` スコープ定義書を、後段の実装依頼（Claude Code への指示）の入力としてそのまま使える粒度で出力する。

### PR-M-10 評価プロトコルの自動セットアップ

- **根拠**: 「Linear Evaluation（線形評価）」が、事前学習済み Base Encoder の重みを完全に固定し、表現 h の上に1層の線形分類器を付加して、少量のラベル付きデータで線形分類器のみを教師あり学習する、と手順を明示している。Table 7 ではラベル比率1%・10%、Top-5 での評価を行っている。
- **要求**: 論文が採用する評価プロトコルを特定し、実行可能な評価スクリプトの雛形を生成する。
- **受入基準の案**: エンコーダの重みが更新されていないことを、実行時に検証して記録する。
- **サブ項目**
  - `PR-S-10-1` Top-1 と Top-5 のどちらで報告された数値かを区別して保持する。
  - `PR-S-10-2` ラベル比率条件（1%、10%）を切り替えて評価できる。

### PR-M-11 論文値と再現値の照合レポート

- **根拠**: 本PDFには、ImageNet で76.5%、Table 7 の Supervised baseline 48.4、SimCLR (ResNet-50) 75.5、(2×) 83.0、(4×) 85.8 など、比較可能な数値が具体的に示されている。

- **サブ項目**

### PR-M-12 限界・課題から後続研究へのマップ

- **根拠**: 「SimCLRの限界と技術課題」が、(1) 大規模計算資源への依存、(2) データ拡張設計のドメイン依存性、(3) 偽陰性（False Negative）問題、の3点を挙げ、「SimCLR以降の発展」が、MoCo v2（メモリキューとモメンタムエンコーダで小バッチでも多数の負例を利用）、BYOL（負例を用いず自己蒸留）を対応づけている。

### PR-M-13 設計思想の抽象化と他ドメイン転用の提示

- **根拠**: 「SimCLRの設計思想: ラベルではなく不変性を教師信号にする」。データ拡張の定義を置き換えることで同じ設計原理を他ドメインへ拡張でき、画像は Crop / Color（外観変化）、分子（MolCLR）は原子マスク・結合切断（構造変化）、ロボティクス（OpenVLA）は視覚表現＋言語・行動への拡張、と対応づけている。
- **要求**: 論文の核となる設計原理を1文で抽出し、「どこを差し替えれば別ドメインに転用できるか」という置換点を明示する。
