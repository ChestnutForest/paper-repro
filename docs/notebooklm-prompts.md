# NotebookLM プロンプト集（paper-repro-mvp 開発ログ用）

paper-repro-mvp の開発ログ（`docs/devlog/devlog-YYYY-MM-DD.md`）を NotebookLM に蓄積し、
チャットで深掘りしたり、スライドを作ったりするための**コピペ用プロンプト集**。

## 使い方

- スライドやチャットで使いたくなったら、該当する「■ コピペ本体」をまるごとコピーして貼る。
- 文面は毎回変えない。各プロンプトが「登録済みの全 devlog を対象にせよ」と指示するので、
  devlog が増えても同じ文面のまま、常に最新の全体が対象になる。
- スライド機能を使う場合は、カスタマイズ欄（「作成するスライドについて説明してください」）に
  スライド用の本体を貼る。

---

# A. スライド作成用（カスタマイズ欄に貼る）

## ■ コピペ本体

このノートブックにある devlog-YYYY-MM-DD.md 形式の開発ログ全ファイル（登録済みの全期間）を対象に、
paper-repro-mvp（英語AI論文の読解〜再現実装ツール）の開発progressレポートのスライドを作成してください。

各スライドは「見出し＋箇条書き3〜5点」で、以下の構成にしてください。
1. 表紙：プロジェクト名／対象期間（最も古い日付〜最新の日付）
2. サマリー：この期間の主な前進を3点
3. 技術・設計の決定：主要な決定と理由（決定→理由の形）
4. つまずきと解決：問題と解決方法の対応
5. Git・環境の歩み：初回pushから現在までの主な操作
6. 用語集：この期間に登場した重要用語（用語＝定義）
7. 現在地と次の一手：最新ログの到達点と翌日の計画

ルール：
- ソースに書かれている内容だけを使い、一般論で埋めないこと
- 各スライドは単独で意味が通るように書き、略語は展開すること
- 時系列の前後を正確に保つこと
- 出典が特定できる項目は日付（YYYY-MM-DD）を添えること

# B. メインチャット用（振り返り・質問）

## B-1. 全体を振り返って整理させる

### ■ コピペ本体

このノートブックにある devlog-YYYY-MM-DD.md 形式の開発ログ全ファイル（登録済みの全期間）を対象に、
paper-repro-mvp プロジェクトのこれまでの歩みを整理してください。

以下の順でまとめてください。各項目は、どの日付のログ由来かを（YYYY-MM-DD）で示すこと。
1. 時系列サマリー：最も古い日付から最新まで、各日に何が前進したかを1日1〜2行で
2. 主要な技術・設計の決定と、その理由（決定ログを集約）
3. つまずきと、その解決方法（同種のものはまとめる）
4. 現在の到達点と、次にやるべきこと（最新ログの「翌日の計画」から）

ソースに書かれていることだけを使い、推測で補わないでください。

## B-2. 知識を試す・思い出す（学習向け）

### ■ コピペ本体

このノートブックの全 devlog の「Q&A 知識カード」を対象に、私の理解度を確認する質問を10問出してください。
1問ずつ出し、私が答えたら、ソースに基づいて正誤と補足を返してください。
出典の日付（YYYY-MM-DD）も示してください。

# C. テーマ別の深掘り（メインチャットに貼る）

## C-1. 決定ログ（なぜその技術・設計を選んだか）

### ■ コピペ本体

このノートブックの全 devlog（登録済みの全期間）を対象に、「決定ログ」に記録された
技術・設計上の決定だけを時系列で抜き出してください。
各決定について、次の3点を表にまとめてください。
- 決定した事項
- 選んだ理由
- 却下した代替案

さらに最後に、これらの決定に一貫している方針（プロジェクトが大事にしている価値観）が
あれば、それを2〜3点で指摘してください。
各項目に日付（YYYY-MM-DD）を添え、ソースに書かれていることだけを使ってください。

## C-2. つまずき（問題と解決）

### ■ コピペ本体

このノートブックの全 devlog（登録済みの全期間）を対象に、「つまずき→解決」に記録された
問題だけを時系列で抜き出し、次を表にまとめてください。
- つまずき（起きた問題）
- 原因
- 解決方法

そのうえで、似た種類の問題をグループ分けし（例：環境設定、Git、ライブラリのバージョン差 など）、
「今後同じ失敗を避けるための教訓」を、グループごとに1つずつ挙げてください。
各項目に日付（YYYY-MM-DD）を添え、ソースにあることだけを使ってください。

## C-3. i18n（多言語対応）

### ■ コピペ本体

このノートブックの全 devlog（登録済みの全期間）を対象に、「i18n（多言語対応）」に
関する記述だけを集めてください。次の順で整理してください。
1. i18n とは何か（このプロジェクトの文脈での定義）
2. なぜ i18n に対応することにしたのか、その決定の経緯
3. どういう方針を採ったか（ライブラリ、書き方のルール、ハードコードの扱い）
4. 現時点で「決めたこと」と「まだ実装していないこと」の区別

専門用語は展開して説明し、各項目に日付（YYYY-MM-DD）を添えてください。
ソースにないことは推測で補わないでください。

## C-4. PostgreSQL（データ永続化）

### ■ コピペ本体

このノートブックの全 devlog（登録済みの全期間）を対象に、「PostgreSQL」および
データベース・データ永続化に関する記述だけを集めてください。次の順で整理してください。
1. なぜ PostgreSQL を選んだのか（他のDB候補と、その却下理由を含む）
2. インメモリ保存から PostgreSQL への移行で、何を追加・変更したのか
3. 移行の途中で起きた問題と、その解決
4. 現時点で完了していること、まだ検証していないこと
5. 将来のDB候補として記録されているものと、その再検討条件

専門用語は展開し、各項目に日付（YYYY-MM-DD）を添えてください。
ソースにあることだけを使ってください。

# 汎用テンプレート（新しいテーマを深掘りするとき）

C-1〜C-4 と同じ型で、テーマ部分だけ差し替えれば新しい串刺し調査ができる。

### ■ コピペ本体

このノートブックの全 devlog（登録済みの全期間）を対象に、「＜テーマ名＞」に関する記録だけを
時系列で抜き出し、コマンド／決定／変更とその効果を一覧にしてください。
各項目に日付（YYYY-MM-DD）を添え、ソースにあることだけを使ってください。

＜テーマ名＞に入れる例：Git操作 / サンドボックス / FastAPI / Docker / ライセンス / スキル / Swagger UI

---

## すべてのプロンプトに共通する設計意図（メモ）

- **「登録済みの全期間を対象」と明示** → devlog が増えても、文面を変えずに常に最新の全体が対象になる。
- **「日付（YYYY-MM-DD）を添える」** → いつの出来事か追える。
- **「ソースにあることだけ・推測で補わない」** → devlog スキルの「捏造しない」制約と揃え、NotebookLMが話を盛るのを防ぐ。
- **テーマ別は「列挙で終わらせず一歩踏み込ませる」** → 決定なら一貫方針、つまずきなら教訓、i18n/PostgreSQLなら「完了と未完了の区別」。
