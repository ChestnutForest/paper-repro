## 1. 選択方法と前提

1〜5から1つだけ選択する。

- 選択肢1〜4: 採用後のシステム動作が異なる具体案。**取り込む範囲が広い順に並べてある**
- 選択肢5: LLMによる自動作成
- 選択完了前は、正本の [`../requirements.md`](../requirements.md) を変更しない
- 選択肢5を選んだ場合、LLMは要求文、採用理由、根拠、影響範囲、受入基準を作成する
- どの選択肢でも、重要な判断、外部送信、公開およびPhase末では人間の明示的な承認を必要とする
- LLMの出力だけで論文の真偽、回答の正しさ、要求の確定を決定しない

### 1.1 なぜこの選択が要るのか

[`../worknotes/id-unification-and-phase-provisional.md`](../worknotes/id-unification-and-phase-provisional.md) 4.2節。

> 画面の背骨は1つしか持てない。ここで Phase 0〜6 を無条件に確定させると、
> 後から別の工程モデルを採用する場合に UI 全体の作り直しになる。

工程モデルを規定する記述が3つ併存しており、`ARF-M-01` が5択を経ていないため
「暫定」と明記するにとどめていた。**本書がその5択である。**

### 1.2 ⚠️ 3案は同じ軸の選択肢ではない

[`../worknotes/workflow-model-three-candidates.md`](../worknotes/workflow-model-three-candidates.md) 3節の読み取り。

| 案 | 対象 | 1回の適用範囲 |
|---|---|---|
| **A. Phase 0〜6** | 製品の工程（仕様抽出→差分特定→仮定台帳→サニティ→照合） | プロジェクト1件 |
| **B. 読解順序**（Title → 著者 → Abstract → 図表 → SI） | 論文1本を読む順序 | 読解1回 |
| **C. Seven Pillars**（Identify → Scope → Plan → Gather → Evaluate → Manage → Present） | 情報リテラシーの枠組み | 研究活動全体 |

**C の前半3段階は、arXiv URL を入力するより前の活動にあたる。**
したがって実質的な選択は「A を背骨として確定させたうえで、B と C から何をどこまで取り込むか」になる。

**選択肢はこの取り込み範囲の広さで並べてある。**

## 2. Y-01：工程モデルの確定

決めることは、**製品の背骨となる工程モデルを確定要件とするか**、
そして確定させる場合に、読解順序と Seven Pillars から何を取り込むかである。

| 番号 | 選択肢 | 採用後の動作 | 長所 | 注意点 | 根拠区分 |
|---:|---|---|---|---|---|
| 1 | **暫定を維持する** | 第1.1節の注記をそのまま残す。実装は Phase 0〜6 で進めるが、工程モデルを確定要件にしない。次サイクルで再検討する | いま決める材料が乏しいまま固定する危険を避けられる。フェーズ0-1（永続化）は背骨に触れないため、実装は止まらない | `REQ-C01` の実装単位が `F-02`（暫定）のまま残り、**Y-01 と `AR-M-03` を判定できない状態が続く。** 保留の理由が「5択を経ていないから」であった以上、5択を実施した本書で再び保留にするのは根拠が弱い | 決定記録 4.3節 |
| 2 | **Phase 0〜6 を維持要求として確定する** | 第1.1節の注記を削除し、Phase 0〜6 を確定要件とする。`F-02` の「暫定」表記も外す。B と C は採らない | 現行の実装・設計・画面がそのまま前提になる。作り直しが生じない。`arxiv-paper-repro` スキルの Phase 0〜6 とも一致する | B の読解順序と C の Scope が持つ利点を取り込めない。**読解経路の工程が、再現実装の工程で代用されたままになる**（`REQ-C01` は両者を同等とする） | 現行 `F-02` |
| 3 | **2に加え、読解順序を Phase 内部の手順として定義する** | Phase 0〜6 を背骨とし、その第1パスの内部手順として Title → 著者 → Abstract → 図表 → SI を定める。`F-01` の「第1パス」の中身を具体化する | 背骨を1つに保ったまま、読解の手順を具体化できる。`F-01` が既に「第1パス（Abstract要約と読む価値の一次判断）」の受け皿を持つ | 論文の種類によって適切な読む順序は変わる。**手順を固定すると、SI を持たない論文などで空の段階が生じる。** プリセットとして切り替え可能にする設計が要る | `PR-M-02` |
| 4 | **3に加え、Scope（知識の欠落の評価）を段階として取り込む** | 3に加え、読解を始める前に「自分の知識の何が足りないか」を評価し記録する段階を置く。結果は `REQ-C02`（前提知識の段階的説明）へ渡す | Seven Pillars が指摘する、**既存の読解順序に欠けている段階**を補える。`REQ-C02` が前提知識を扱う以上、欠落の評価と接続が自然 | 段階が1つ増え、利用者の初期負担が増える。**欠落の評価をLLMが行うと、`REQ-C04-S02` の「流暢さだけで理解済みにしない」と同じ危険がある。** 人間の確認が要る | `ARF-M-01`（REF-07） |
| 5 | LLMによる自動作成 | LLMが要求文、採用理由、根拠、影響範囲、受入基準を作成する | 選択肢1〜4の枠に収まらない案が出る可能性がある | **工程モデルは画面の背骨であり、影響範囲が最も大きい要求のひとつである。** LLM の案をそのまま採るのは危険が大きい | — |

## 3. 選択にあたっての判断材料

### 3.1 確定を急ぐ理由と、急がない理由

**急ぐ理由。** 保留の理由は「`ARF-M-01` が5択を経ていないから」だった。
本書がその5択である以上、**保留の前提は解消されている。**
また Y-01 と `AR-M-03` が判定できず、要求の突合が完了しない。

**急がない理由。** 決定記録 117〜118行は「実装は Phase 0〜6 で進めてよい」としている。
次の実装であるフェーズ0-1（`projects` / `papers` の永続化）は
**データ層の作業であり、画面の背骨に触れない。**

### 3.2 影響範囲

| 選択肢 | `requirements.md` | `F-01`・`F-02` | データモデル |
|---|---|---|---|
| 1 | 変更なし | 変更なし | 変更なし |
| 2 | 第1.1節の注記を削除 | `F-02` の「暫定」表記を外す | 変更なし |
| 3 | 2に加え `REQ-C02-S01` の具体化 | `F-01` の第1パスの中身を定義 | 読解の進行状態を持つ必要がありうる |
| 4 | 3に加え新しい段階の要求文 | `F-01` の前に段階が1つ増える | 知識の欠落の記録が要る |

⚠️ **選択肢3・4はデータモデルに影響する。** 17エンティティのうち物理仕様が確定しているのは
`Project`／`Paper` だけであり、残る15件は利用フェーズ直前に確定する方針である
（[`../arch-guide/arc-artifact-order.md`](../arch-guide/arc-artifact-order.md)）。
**いま確定させても、物理仕様の作業はフェーズ1以降になる。**

### 3.3 `REQ-C01` との整合

`REQ-C01` は読解・学習と再現実装を**同等の主要経路**と定める。
現行の Phase 0〜6 は再現実装の工程であり、**読解経路の固有の工程を持たない。**

選択肢2を選ぶと、この不均衡が確定する。選択肢3・4は不均衡を減らす方向にある。
**ただし読解経路に独自の工程が要るかどうか自体が、まだ検討されていない。**
