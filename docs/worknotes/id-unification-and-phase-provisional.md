## 2. 決定1：ID体系を `REQ-Cxx` に一本化する

### 2.1 決定内容

- `REQ-Cxx`（および `REQ-Cxx-Sxx`）を要求の**一次識別子**とする。
- `F-xx` / `B-xx` / `N-xx` は、機能の粒度（画面・API・非機能条件の単位）を示す
  **二次識別子**として維持する。新しい番号は振り直さない。

### 2.2 理由

`F-xx` に寄せる案と比較した。

| 観点 | `REQ-Cxx` に寄せる | `F-xx` に寄せる |
|---|---|---|
| 追跡可能性が集中している場所 | 決定台帳3冊、分析文書19本、変更案が既にこの体系 | v0.1 の `requirements.md` のみ |
| 番号の読み替えが必要な範囲 | なし（既存資料はそのまま参照できる） | 決定台帳・分析文書・変更案の全19+件を読み替える必要がある |
| 機能の粒度を示す情報 | `F-xx` を二次識別子として残せば失われない | — |

`REQ-Cxx` を一次識別子にすれば、既存の19本の分析文書・3冊の決定台帳・変更案を
一切書き換えずに済む。`F-xx` に寄せる場合はその全部で番号の読み替えが生じ、
かつ後から新しい一次資料（`simclr-handson-deck.md` など）を追加するたびに
同じ読み替えを繰り返すことになる。

### 2.3 対応表の扱い

対応表は `requirements.md` 内に置いた（「ID対応表（要求文統合前の暫定版）」の章）。
理由は、対応表が要求文そのものと同じ文書に無いと、要求文を統合する作業のたびに
2つの文書を突き合わせる手間が生じるため。対応表は3群に分けた。

1. **維持**（`REQ-Cxx` 対応なし）— 一次資料と矛盾せず、番号も内容も変更しない18項目
2. **修正**（既存IDのまま内容を更新）— 13項目
3. **新規提案**（変更案のみに存在し、本書にはまだ未反映）— 13項目

3群目は、要求文統合の段階で「新規追加するか、既存項目への追記に代えるか」を
改めて判断する。本書では追加していない。

## 3. 決定2：「再現」の語の水準を明示する

### 3.1 決定内容

`requirements.md` に「0. 用語定義」の章を新設し、
ACM Artifact Review and Badging v1.1（[`../references.md`](../references.md) REF-10）の
3水準（Repeatability / Reproducibility / Replicability）を明記した。
初期リリース（タイプB・公式実装あり）は主に Reproducibility を目指すと明記した。

### 3.2 理由

`REQ-C05`・`REQ-C08`・`REQ-C10-S02` はいずれも「再現」を前提とするが、
どの水準かが書かれていなかった。ACM は Reproducibility と Replicability の定義を
過去に入れ替えた経緯があり、コミュニティによって逆に使われてきた語である。
定義を書かずに要求文を統合すると、後から `ARF-M-02`（再現の3水準の明示、
[`../requirements-analysis/academic-research-skills-frameworks.md`](../requirements-analysis/academic-research-skills-frameworks.md)）
を採る段階で語の再定義が必要になり、影響が3件の要求文へ波及する。
先に定義しておけば、この波及が起きない。

### 3.3 未実施のこと

`ARF-M-02` 自体（水準を利用者が選択できる機能）は、まだ5択を経ていない。
今回定義したのは**製品が使う語の意味**であり、**その水準を選ぶ機能**ではない。
機能化は次サイクルで判断する。

## 4. 決定3：Phase 0〜6 を暫定と明記する

### 4.1 決定内容

`requirements.md` の目的の章と、F-02（パイプライン・ウィザード）の行に、
Phase 0〜6 が暫定の工程モデルであることを明記した。

### 4.2 理由

工程モデルを規定する記述が3つ併存している。

| 出典 | 工程 |
|---|---|
| `requirements.md` v0.1 の F-02 | Phase 0〜6 のステッパー |
| 書籍由来の分析／`simclr-handson-deck.md` の `PR-M-02` | Title → 著者 → Abstract → 図表 → SI |
| `academic-research-skills-frameworks.md` の `ARF-M-01`（SCONUL Seven Pillars） | Identify → Scope → Plan → Gather → Evaluate → Manage → Present |

画面の背骨は1つしか持てない。ここで Phase 0〜6 を無条件に確定させると、
後から別の工程モデルを採用する場合に UI 全体の作り直しになる。

一方で、`ARF-M-01` はまだ5択を経ておらず、いま確定させると根拠なく決めることになる。
そこで「暫定」と明記するにとどめた。**実装は Phase 0〜6 で進めてよい。** 止めているのは
工程モデルを設計の恒久的な前提として固定することだけである。

### 4.3 未実施のこと

工程モデルそのものの確定は行っていない。次サイクルで `ARF-M-01` を5択にかけるか、
Phase 0〜6 を維持要求として確定させるかを判断する。
