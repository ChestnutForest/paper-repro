## 1. 何を記録するか

**第三者による再現結果と、自分の再現結果を比較する機能。**

いわゆるリーダーボード（`<Task, Dataset, Metric>` ごとの SOTA 一覧）が提供していた種類の
情報を、照合工程で使う案である。

## 2. なぜこの案が出たか

### 2.1 現状の照合

[`../arch-guide/arc-behavior-list.md`](../arch-guide/arc-behavior-list.md) の
`B-05-001`「再現値と論文値を照合する」は、次の2つを突き合わせる。

| 比較対象 | 入手元 |
| --- | --- |
| 論文が主張する値 | **論文本文から読み取る** |
| 自分の再現結果 | サンドボックスでの実行結果 |

**第三者の再現結果は含まれていない。**

### 2.2 想定される場面

再現値が論文値と食い違ったとき、原因の切り分けに次の情報が役立ちうる。

| 状況 | 第三者の結果が示すこと |
| --- | --- |
| 他の人も同じ値になっている | **自分の実装は正しい。** 論文値の方に問題がある可能性 |
| 他の人は論文値を再現できている | **自分の実装に誤りがある可能性** |
| 誰も再現できていない | 論文の記述に不足がある可能性 |

**「自分だけが失敗しているのか」を判断できる。** これは `REQ-C10`（批判的検証）の
観点と親和する。

## 3. なぜ今回は開発しないか

| 理由 | 内容 |
| --- | --- |
| **要求が無い** | 確定要求 `REQ-C01`〜`REQ-C11` に対応するものがない |
| **入手先が不安定** | PwC 終了により、SOTA情報の主要な供給源が失われた |
| **MVP の範囲外** | 1本の論文を再現する縦切りに、比較機能は含まれない |
| **利用者が論文を選ぶ段階が製品の外** | 比較して選ぶ場面が現状は存在しない |

### 3.1 ⚠️ PwC 終了との関係

[`decision-pwc-replacement.md`](decision-pwc-replacement.md) では、
**必要なのは「論文と実装の紐付け」だけ**と判断し、Hugging Face Papers API へ差し替えた。

**この判断は、比較機能を要求としないことを前提としている。**
本書の案が要求になれば、その前提が変わる。

| 前提が変わった場合 | 検討が必要になること |
| --- | --- |
| 比較機能を要求とする | Hugging Face だけでは足りない可能性 |
| SOTA 情報が必要 | CodeSOTA など後継サービスの再検討 |

## 4. 要求化するときに決めること

将来この案を要求として立てる場合、次を決める必要がある。

| # | 決めること | 論点 |
| --- | --- | --- |
| 1 | **情報源** | どこから第三者の再現結果を得るか。継続性のある供給源があるか |
| 2 | **信頼性の扱い** | 第三者の結果をどこまで信じるか。`REQ-C07`（情報源の優先順位）に従う |
| 3 | **食い違いの表示** | 論文値・自分の値・第三者の値が三つ巴で食い違う場合の見せ方 |
| 4 | **再現条件の同一性** | 環境・データ・ハイパーパラメータが違えば比較にならない |
| 5 | 対応する要求ID | 既存要求の下位とするか、新規メイン要求とするか |

### 4.1 ⚠️ 特に4番が難しい

**再現条件が違えば、値が違って当然である。** 単に数値を並べても比較にならない。

`BR-10`（証拠・由来・不確実性）に従えば、**条件の差を明示せずに数値だけ並べてはならない。**
第三者の結果に条件が記録されていなければ、比較の根拠にならない。
