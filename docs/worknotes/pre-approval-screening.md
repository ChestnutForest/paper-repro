## 1. なぜ承認の前にこれを行ったか

承認したあとで「新しい分析が既存の選択と矛盾していた」と判明するのが最悪の順序である。
承認を取り消すことになり、決定台帳の履歴が汚れる。

一方で、32件を1件ずつ既存要求へ対応付ける全面突合は数日を要し、
それを待つと熟した11件の確定が止まる。

そこで**矛盾の有無だけ**を見る安価な確認を先に行い、承認可否の判断材料とした。

### 1.1 やらなかったこと

- 32件の採否の判断
- 32件と既存要求の対応付け（重複判定）
- 暫定ID（`PR-M-xx` / `AR-M-xx` / `ARF-M-xx`）から `REQ-Cxx` 体系への合流
- 5択の実施

これらは承認後の次サイクルで行う。

## 4. 承認時に手当てすべき2件

### 4.1 空白1：工程モデルが三重に存在している

現在、製品の工程を規定する記述が3つ併存している。

| 出典 | 工程 |
|---|---|
| `requirements.md` v0.1 の `F-02` | Phase 0〜6 のステッパー |
| 書籍由来の分析／`PR-M-02` | Title → 著者（所属）→ Abstract → 図表 → SI |
| `ARF-M-01`（SCONUL Seven Pillars） | Identify → Scope → Plan → Gather → Evaluate → Manage → Present |

**画面の背骨は1つしか持てない。** v0.2 を確定させると Phase 0〜6 が確定要件になり、
後から別の工程モデルを採ると UI 全体の作り直しになる。

ただし、**承認対象そのものは無傷である。** `REQ-C01`〜`REQ-C11` の要求文はいずれも工程モデルを
規定していない（`REQ-C01` は主要経路の選択を述べるにとどまる）。矛盾しているのは v0.1 の
`F-02` との間だけである。

**手当て**: v0.2 へ統合する際、Phase 0〜6 を「確定」ではなく**「暫定」と明記**し、
工程モデルの確定を次サイクルの決定事項として残す。5択を開き直す必要はない。

### 4.2 空白2：「再現」という語の水準が定義されていない

`REQ-C05`（論文値照合を支援範囲とする）、`REQ-C08`（由来の追跡）、`REQ-C10-S02`（実験条件の構造化）は
いずれも「再現」を前提とするが、**どの水準の再現かが書かれていない**。

ACM Artifact Review and Badging v1.1（[`../references.md`](../references.md) の REF-10）は3水準を区別する。

| 用語 | 定義 |
|---|---|
| Repeatability | 同一チーム・同一実験設定 |
| Reproducibility | 異なるチーム・同一実験設定（**著者の成果物を使う**） |
| Replicability | 異なるチーム・異なる実験設定（**著者の成果物を使わない**） |

ACM は NISO の勧告により後者2語の定義を入れ替え、過去のバッジ表示も遡って統一した経緯を明記している。
つまりコミュニティによって逆に使われてきた語である。

定義を書かずに v0.2 を確定させると、`ARF-M-02` を後から採る段階で**要求文の語を再定義することになり、
`REQ-C05`・`REQ-C08`・`REQ-C10-S02` の3件へ波及する**。

**手当て**: v0.2 に**用語定義の節を1つ足し、ACM v1.1 のどの水準を指すかを明記する**。
要求文そのものの変更は不要である。
