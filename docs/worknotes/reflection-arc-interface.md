## 最大の論点：対象領域が合わない

ガイドの定義は次である。

> 開発対象となる**業務システム**とそれ以外の**業務システム**との間で発生するデータのやりとり

**企業の業務システム間連携を想定している。** 受注データを基幹系へ送る、といった場面。

`paper-repro` の連携先は arXiv・GitHub・Claude API であり、**業務システムではない。**
ガイドが前提とする「相手システムの担当者と仕様を合意する」構図が成り立たない。
仕様は先方が一方的に定め、こちらは従うだけである。

### ガイドの区分が機能しない

| ガイドの区分 | paper-repro での該当 |
| --- | --- |
| 同一企業内で同一システム | なし |
| 同一企業内の外部システム | なし |
| 社外の外部システム | **全部** |
| 新規 / 既存で変更要 / 既存で変更不要 | **全部が「既存で変更不要」** |

**区分しても扱いが変わらない。** 列は残すが、全行同じ値になる旨を注記した。

### 代わりに独自の区別を足した

| 区別 | なぜ重要か |
| --- | --- |
| 課金の有無 | コスト上限の管理対象が変わる |
| レート制限 | 違反すると遮断される |
| 失敗時の影響 | どこまで縮退できるかが変わる |
| 代替の可否 | 障害時の設計が変わる |

一覧表に★印の列として追加する。

## 固定長ファイル前提の項目がある

項目説明の構成要素に「全体レコード長」「可変長・固定長区別」がある。
**これは固定長ファイルでのやりとりを想定した項目**であり、
JSON でやりとりする `paper-repro` には該当しない。

→ 該当しない項目は「—」とし、代わりに**JSONのネスト構造を階層レベルで表す**と決めた。

## 「保存期間」「保存場所」が重要になる

処理説明の構成要素にある。ガイドでは運用上の項目だが、
`paper-repro` では**著作権とライセンスに直結する。**

論文本文をどれだけ保持してよいかは arXiv のライセンスによって決まる。
9章の未解決事項に挙げた。

## 振舞い編との責務分担を定めた

`arc-behavior.md` 7.4節が共通ルールに「外部API呼び出しの規則」を含めるとしている。
重複を避けるため境界を明確にした。

| 対象 | 担当 |
| --- | --- |
| 何をやりとりするか | 本書 |
| データ項目の定義 | 本書 |
| 呼び出しの手順・事前条件・終了条件 | 本書 |
| 失敗時に業務をどう進めるか | 振舞い編 |
| コスト上限に達したときの停止 | 振舞い編 |

## 完了判定に「先方の公式仕様との突き合わせ」を入れた

**外部インタフェースの仕様はこちらが決められない。**
推測で書いた仕様書は実装時に必ず食い違う。

充実の条件に「公式ドキュメントのURLと参照日を記録」を必須とした。

また「**失敗時に業務が止まらないテスト**」を完成の条件に入れた。
外部システムはこちらの都合と無関係に落ちる。
