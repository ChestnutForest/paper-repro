# 未整備の共通ルール：外部API呼び出し（`BR-13`）

- 対象プロダクト: `paper-repro`
- 文書種別: 未整備事項の記録
- 作成日: 2026年8月31日
- 発見の契機: [`../arch-guide/arc-interface.md`](../arch-guide/arc-interface.md) 2.3節の前提を検証したとき
- 状態: **未着手。外部IF一覧の作成と同時に対応する**

---

## 何が問題か

`arc-interface.md` 2.3節は、外部API呼び出しの規則を
[`../arch-guide/arc-behavior-rules.md`](../arch-guide/arc-behavior-rules.md) が扱うと定めた。
根拠は [`../arch-guide/arc-behavior.md`](../arch-guide/arc-behavior.md) 7.4節が
共通ルールに「外部API呼び出しの規則」を含めるとしていたことである。

**しかし、`arc-behavior-rules.md` v0.1 に当該規則は無かった。**

## 検証結果

| 規則 | 状況 |
| --- | --- |
| 外部サービスの識別（arXiv、GitHub、LLM API） | ✅ `BR-02` |
| 取得値に取得元・取得日時・対象版を伴わせる | ✅ `BR-02` |
| APIエラーの表示（安定コードと人向けメッセージ） | ✅ `BR-07` |
| 著作権・ライセンスの保存 | ✅ `BR-08` |
| **レート制限** | ❌ 無い |
| **コスト上限と、達したときの停止** | ❌ 無い |
| **リトライ・タイムアウト** | ❌ 無い |
| **呼び出し失敗時の縮退** | ❌ 無い |

### ⚠️ `BR-12` は該当しない

`BR-12`「非同期処理とサンドボックス」は名前が近いが、**隔離実行環境の規則**である。

> ネットワークは原則遮断し、許可先が必要な場合は明示的に制御する。

**外部APIを呼ぶ文脈とは逆**であり、外部API呼び出しの規則としては使えない。

### `BR-04` も該当しない

`BR-04` に「コストや利用量の期間は、単位とタイムゾーンを明示する」とあるが、
これは**表示単位の話**であり、上限やその超過時の挙動を定めていない。

## なぜ本書側で定義しないか

`arc-interface.md` で定義すると、**責務が二重になる。**

- 共通ルールは振舞い編が持つ、という構造を崩す
- 個別業務が参照すべき規則が2箇所に分かれる
- 振舞い編の `BR-nn` 体系と番号が繋がらない

**`arc-behavior-rules.md` へ `BR-13` として追記するのが正しい。**

## `BR-13` に書くべき内容（案）

⚠️ **具体値は未確認である。** 各サービスの公式ドキュメントを参照してから確定する。

| 観点 | 定めるべきこと |
| --- | --- |
| レート制限 | 各サービスの制限値を守る。超えないよう間隔を制御する |
| コスト上限 | 従量課金の上限。達したときに何を止め、何を続けるか |
| リトライ | 再試行の可否をエラー種別で分ける。回数と間隔 |
| タイムアウト | 待ち時間の上限。超えたときの扱い |
| 失敗時の縮退 | どの業務が止まり、どこまで進められるか |
| 利用規約 | 自動取得の可否、再配布の可否 |

## いつ対応するか

**外部IF一覧（`arc-interface-list.md`）の作成と同時。**

理由は、一覧を作る過程で各サービスの公式ドキュメントを参照するため、
レート制限や課金条件がそこで判明するからである。先に規則だけ書くと、
具体値が入らない空の規則になる。
