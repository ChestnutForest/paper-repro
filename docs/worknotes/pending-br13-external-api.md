# 未整備の共通ルール：外部API呼び出し（`BR-13`）

- 対象プロダクト: `paper-repro`
- 文書種別: 未整備事項の記録
- 作成日: 2026年8月31日
- 更新日: 2026年8月31日（GitHub 認証の決定を反映）
- 発見の契機: [`../arch-guide/arc-interface.md`](../arch-guide/arc-interface.md) 2.3節の前提を検証したとき
- 状態: **未着手。外部IF一覧の作成と同時に対応する**

---

## 何が問題か

`arc-interface.md` 2.3節は、外部API呼び出しの規則を
[`../arch-guide/arc-behavior-rules.md`](../arch-guide/arc-behavior-rules.md) が扱うと定めた。
根拠は [`../arch-guide/arc-behavior.md`](../arch-guide/arc-behavior.md) 7.4節が
共通ルールに「外部API呼び出しの規則」を含めるとしていたことである。

**しかし、`arc-behavior-rules.md` v0.1 に当該規則は無かった。**

## 検証結果

| 規則 | 状況 |
| --- | --- |
| 外部サービスの識別（arXiv、GitHub、LLM API） | ✅ `BR-02` |
| 取得値に取得元・取得日時・対象版を伴わせる | ✅ `BR-02` |
| APIエラーの表示（安定コードと人向けメッセージ） | ✅ `BR-07` |
| 著作権・ライセンスの保存 | ✅ `BR-08` |
| **レート制限** | ❌ 無い |
| **コスト上限と、達したときの停止** | ❌ 無い |
| **リトライ・タイムアウト** | ❌ 無い |
| **呼び出し失敗時の縮退** | ❌ 無い |

### ⚠️ `BR-12` は該当しない

`BR-12`「非同期処理とサンドボックス」は名前が近いが、**隔離実行環境の規則**である。

> ネットワークは原則遮断し、許可先が必要な場合は明示的に制御する。

**外部APIを呼ぶ文脈とは逆**であり、外部API呼び出しの規則としては使えない。

### `BR-04` も該当しない

`BR-04` に「コストや利用量の期間は、単位とタイムゾーンを明示する」とあるが、
これは**表示単位の話**であり、上限やその超過時の挙動を定めていない。

## なぜ本書側で定義しないか

`arc-interface.md` で定義すると、**責務が二重になる。**

- 共通ルールは振舞い編が持つ、という構造を崩す
- 個別業務が参照すべき規則が2箇所に分かれる
- 振舞い編の `BR-nn` 体系と番号が繋がらない

**`arc-behavior-rules.md` へ `BR-13` として追記するのが正しい。**

## `BR-13` に書くべき内容

⚠️ **一部は確定済みである。** 外部IF一覧の作成過程で公式仕様を調査した結果を反映する。

### 確定した値

| インタフェース | 制限 | 出典 |
| --- | --- | --- |
| `IF-01` arXiv | **1リクエスト/3秒**、同時接続1本 | 公式ドキュメント（2026-08-31 参照） |
| `IF-02` GitHub | 未認証 60/時、**認証 5,000/時** | 同上 |
| `IF-04` OpenReview | 1回あたり最大1,000件 | 同上 |
| `IF-03` Hugging Face | **未確認** | — |
| `IF-05` LLM | プロバイダ依存 | — |

### 確定した認証方式

| インタフェース | 認証 | 決定記録 |
| --- | --- | --- |
| `IF-02` GitHub | **fine-grained PAT**（`Authorization: Bearer`） | [`decision-github-auth.md`](decision-github-auth.md) |
| `IF-01` arXiv | 不要 | — |
| `IF-03` Hugging Face | 不要 | — |
| `IF-04` OpenReview | 任意（ゲスト可） | — |
| `IF-05` LLM | 必要 | — |

### まだ定めるべきこと

| 観点 | 定めるべきこと |
| --- | --- |
| **コスト上限** | 従量課金は `IF-05` のみ。上限値と、達したときに何を止め何を続けるか |
| **リトライ** | 再試行の可否をエラー種別で分ける。回数と間隔 |
| **タイムアウト** | 待ち時間の上限。超えたときの扱い |
| **失敗時の縮退** | どの業務が止まり、どこまで進められるか |
| **残量の監視** | `X-RateLimit-Remaining` をどう扱うか |
| **認証情報の保管** | 環境変数。`BR-08` の範囲だが、外部APIに特化した規則が要る |

### ⚠️ 特に扱いが要る事項

| 事項 | 内容 |
| --- | --- |
| **429 が制限内でも返る** | arXiv で報告あり。制限を守っても失敗しうる前提で設計する |
| **空の結果と取得失敗の区別** | OpenReview は誤ったURLでもエラーにならず空が返る（`BR-10`） |
| **未索引と存在しないの区別** | Hugging Face は全論文を索引していない |
| **トークン期限切れ** | fine-grained PAT は最長366日。401 を障害と誤表示しない |

## いつ対応するか

**外部IF一覧の作成と同時**としていたが、**一覧は v0.3 まで進んだ。**

残るのは `interfaces/`（項目説明・処理説明）の作成である。
**`BR-13` はそれより先に定めるのが順序として正しい。** 個別の処理説明が
共通ルールを参照するためである。
