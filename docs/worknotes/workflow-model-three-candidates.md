## 3. ⚠️ 3案は階層が違う

**本書の中心的な読み取りである。** 決定記録は3案を「工程モデルを規定する記述が3つ併存している」
と並列に扱っているが、**内容を読むと対象も粒度も異なる。**

| 案 | 対象 | 粒度 | 1回の適用範囲 |
|---|---|---|---|
| A | **製品の工程** | 論文1本の読解から再現実装までの全体 | プロジェクト1件 |
| B | **論文1本を読む順序** | 1本の論文の中をどう辿るか | 読解1回 |
| C | **情報リテラシーの枠組み** | 文献を見つけ・評価し・整理する研究活動 | 研究活動全体 |

### 3.1 C は論文1本の工程ではない

Seven Pillars の Gather（入手する）と Present（提示する）は、**文献調査全体の流れ**である。
`paper-repro` は「arXiv URL を入力すると」始まる製品であり、
**Identify（情報の必要性に気づく）・Scope（欠落を評価する）・Plan（探索の戦略を組む）は
入力より前の活動にあたる。**

⚠️ ただし [`../requirements-analysis/academic-research-skills-frameworks.md`](../requirements-analysis/academic-research-skills-frameworks.md) 59行は、
**Scope（自分の知識の欠落を先に評価する）が既存の読解順序に欠けている段階**だと指摘している。
枠組み全体を採らずとも、**この1段階だけを取り込む余地はある。**

### 3.2 B は A の内部に収まりうる

`PR-M-02` の Title → 著者 → Abstract → 図表 → SI は、論文1本を最初に読む手順である。
Phase 0〜6 でいえば、**仕様抽出の前段（第1パス）にあたる。**

[`../requirements.md`](../requirements.md) 336行の `F-01`（論文入力）は既に
「第1パス（Abstract要約と「読む価値」の一次判断）を表示」と定めており、**受け皿がある。**

### 3.3 したがって「どれか1つを選ぶ」問いではない可能性がある

A を製品の背骨とし、B をその内部の手順とし、C は採らない（または Scope だけ取り込む）
という組み合わせが成り立つ。

⚠️ **決定記録の「画面の背骨は1つしか持てない」は正しい。** ただし背骨が1つであることと、
**3案が同じ軸の選択肢であること**は別である。背骨は A、その内部の手順は B、という構成は
背骨を2つ持つことにはならない。

## 4. Seven Pillars の性質のうち、現行と整合するもの

[`../requirements-analysis/academic-research-skills-frameworks.md`](../requirements-analysis/academic-research-skills-frameworks.md) 56行が
重要な性質を挙げている。

> 各柱の内部で初心者から熟達者へ向かうが、**情報環境が変わるため柱を降りることもある**。
> 習熟は一方向ではない。

これは Phase 0〜6 の直線的な工程とは思想が異なる。ただし現行と矛盾しない。

| 現行の記述 | 対応 |
|---|---|
| `REQ-C01` 「進捗を失わず切り替えられる」 | 非直線性を許容している |
| Y-01（`ARF-M-01`＋`PR-M-02`）「段階は前後に行き来できる」 | 同上 |
| `F-02` 「各 Phase を行き来できる」 | 同上 |

**非直線性という点では3案とも一致している。** 争点はそこではない。

⚠️ また、同57行が Seven Pillars に **Research Lens**（研究者向けのレンズ）があり
Vitae RDF（REF-09）へ対応づけられていると述べている。これは
`ARF-M-12`（熟達段階に応じた支援の粒度調整。突合02で 🆕）と繋がる。
**Seven Pillars を採らなくても、熟達段階の概念だけは別要求として残りうる。**

## 5. 5択へ送る論点

### 論点1: 製品の背骨を何にするか

選択肢の軸は「A を維持要求として確定させる／C へ全面的に揃える／確定させないまま進む」である。

⚠️ **C への全面移行は現実的でない見込みである。** 3.1節のとおり、C の前半3段階は
製品の入力より前の活動にあたる。ただし**本書は採否を決めない。**

### 論点2: B をどこに置くか

A の内部（第1パスの手順）とするか、独立した工程モデルとするか。
`F-01` に受け皿がある点が判断材料になる。

### 論点3: C から部分的に取り込むか

Scope（知識の欠落を先に評価する）と Research Lens（熟達段階）の2点は、
枠組み全体を採らずとも取り込みうる。
後者は `ARF-M-12` として既に別の候補になっている。

### 論点4: 確定させないという選択肢を残すか

決定記録は「実装は Phase 0〜6 で進めてよい」としており、**確定しなくても実装は止まらない。**
確定を急ぐ理由が UI の作り直しを避けることだけなら、
**フェーズ0-1（永続化）の段階では背骨に触れないため、まだ急がない**という判断もありうる。
