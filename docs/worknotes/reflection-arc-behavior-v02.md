### 誤りの原因

**画面編が6成果物であったため、振舞い編も6つだと推測した。**
実際は4つで、名称も大きく異なっていた。

「業務フロー」を独立成果物とした点、「状態遷移」を成果物とした点が、
特に事実と違っていた。

### 教訓

**一次資料を入手せずに枠組みを書くと、隣接分野からの類推で誤る。**
画面編で誤りが無かったのは偶然に近い。今後、本文未入手のまま枠組みを書く場合は、
**「未検証である」ことを本文中で明示する**必要がある。

## v0.2 で追加した重要な観点

### ① システム利用作業と機能の区別（2.4節）

**原文はシステム化業務を2種類に分けている。** これが本書の要となった。

| 種別 | 定義 |
| --- | --- |
| システム利用作業 | 人とシステムのやり取りに関わる処理 |
| 機能 | システムによって自動化される処理 |

**この区別は `paper-repro` の human-in-the-loop 設計と直結する。**
承認ゲートはシステム利用作業であり、自動化してはならない。

フェーズ0-1で起きた「承認ゲートを通り抜ける実装」は、
**システム利用作業を機能として扱った誤り**として説明できる。

6.1節の機械検査に「承認を伴う業務が、機能でなくシステム利用作業になっているか」を
追加した。

### ② 記述粒度（3.3節）

原文は「**場所・時間・作業者**で区分される業務の単位」と定めている。
`paper-repro` では次のように読み替えた。

| ガイド | 読み替え |
| --- | --- |
| 場所 | 画面（`S-nn-mm`） |
| 時間 | フェーズ（Phase 0〜6） |
| 作業者 | 利用者／システム／外部サービス |

**外部システムのシステム化業務は記述範囲外**という原文の規定に従い、
arXiv・GitHub・Claude API 側の処理は扱わないと明記した。

### ③ 状態遷移の位置づけを変更（3.4節）

v0.1 は状態遷移を「最優先の工程成果物」としていたが、**ガイドの成果物ではない。**

扱いを次のとおり改めた。

- ガイド準拠の4成果物とは**別扱い**の補助資料とする
- `arc-behavior-state.md` として独立させる
- 文書の冒頭に**ガイド準拠の枠外であることを明記**する

**「ガイドに準拠した成果物」と「独自の追加」を混ぜない。**
混ぜると、どこまでがガイド由来か判断できなくなる。

### ④ 工程成果物間の関連（第8章）

前身の第5章にあった観点を復活させた。画面編の第8章と同じ趣旨である。

## ID体系の変更

**処理ID を `P-nn-mmm` から `B-nn-mmm`（Business）へ変更した。**
原文の用語が「処理」ではなく「システム化業務」であるため。

⚠️ **画面編 4.1節が `A-nn-mmm` と `P-nn-mmm` を揃えると書いている。**
`B-nn-mmm` への変更に伴い、画面編側の記述も修正が必要である。

## 著作権上の配慮

参照したのは次の**著作物にあたらない事実**に限る。

- 工程成果物の名称（4つ）と、その定義の要約
- システム利用作業と機能の区別
- 記述粒度の区分（場所・時間・作業者）
- 記述範囲外の規定
- 共通ルールの記述内容の項目名
- 前身が第5章に「工程成果物間の関連」を持っていたこと

**第3部「合意形成のコツ」の本文は、転記も言い換えもしていない。**
