## なぜ`REQ-C07-S02`と分けたのか

「1.2.3.2」で確定した`REQ-C07-S02`（補完源の管理）に含めることも検討したが、
**情報の性質が根本的に異なる**ため分けた。

| 観点 | 照会（1.2.3.2） | 公開議論（1.2.3.3） |
| --- | --- | --- |
| 発言者 | 論文の著者本人 | 不特定多数 |
| 内容の質 | 効果的な回答が期待できる | 的外れなコメントを含む |
| 取得の確実性 | 6〜7割は返信 | 運の要素が大きい |
| 文脈 | 個別に前提を説明できる | 短文で前提の共有が難しい |

同一に扱うと、**著者本人の回答と匿名の的外れなコメントが区別できなくなる**。
`REQ-C07:4`の「矛盾を消さず、人間が採用理由を決める」を実装可能にするには、
この区別が必要である。

## 特に重要な受入基準

- **発言者が著者本人であることが確認できない場合、確認済みとして表示しない**
  → SNS上の「著者らしき人物」を著者の見解として扱わない
- **賛同数・閲覧数を内容の正しさの指標として提示しない**
  → 反応量と正しさは無関係
- **外部サービスの利用規約に反する自動収集を行わない**
  → X、Redditの取得条件に配慮
- **特定サービスが利用不能になっても取得済み記録を参照できる**
  → 本文がalphaXivを「試験的で将来は非自明」と明記していることへの対応

## 図1.8について

alphaXivの画面例（論文の特定箇所へのコメントに著者が回答）から、
**「論文の特定箇所に紐づく議論」**という形態を抽出した。
これは`REQ-C09-S01`（電子的読解と注釈）が扱う注釈と構造が近い。

将来、外部の議論を自分の注釈と並べて参照する設計が考えられるが、
本分析では記録の枠組みまでに留めた。
