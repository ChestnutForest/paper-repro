# CCAF適用率の再計測 運用手順

`ccaf-coverage-YYYY-MM-DD.md`（適用率レポート）を再計測して更新するための手順。
算定規則そのものは `coverage-rubric.md`、設計指針は `README.md` を参照。

> **実施頻度：毎日ではなく「節目」で行う。**
> 日々の作業手順は [`../daily-routine.md`](../daily-routine.md) を参照。
> 適用率は機能が実装されて初めて動くため、毎日測っても同じ数値が並ぶだけになる。

---

## 「前回ファイル」とは何か

**ひとつ前に計測したときの適用率レポートそのもの**を指す。現時点では次のファイル。

```
docs/arch-guide/ccaf-coverage-2026-08-03.md
```

次に再計測するとき（例：`ccaf-coverage-2026-09-XX.md` を作るとき）、この8月3日版が「前回ファイル」になる。

## なぜ前回ファイルを渡す必要があるのか

**Claude は過去のチャットの内容を保持していない。**
新しいチャットで「CCAF適用率を出して」と言っても、前回が何%だったか、
どのタスクが適用済だったかを知る手段がない。

スキル `paper-repro-arch-guide` には
「**前回ファイルが無ければ、前回比を捏造せず『初回計測』と明記する**」というルールがある。
そのため、貼らなくても計測自体はできるが、その場合は毎回「初回計測」扱いになり、**変化が追えない**。

## 渡し方（どちらでもよい）

前回ファイルは手元のリポジトリ内（`docs/arch-guide/`）にある。

1. **ファイルをアップロードする** — `ccaf-coverage-YYYY-MM-DD.md` をそのまま添付する
2. **中身を貼り付ける** — エディタで開いてコピー＆ペーストする

**最新の1本だけ渡せば十分。** 全履歴を貼る必要はない（差分は直前との比較で取るため）。

## 貼る場合と貼らない場合の違い

### 貼らない場合

```
総合適用率: 28.5%
前回比: 初回計測
```

### 貼った場合

```
総合適用率: 28.5%
前回比: +13.3pt（15.2% → 28.5%）

今回上がったタスク:
- D4 4.3 tool_use + JSONスキーマ : 未適用 → 適用済（証拠: フェーズ1実装、コミットxxx）
- D4 4.2 few-shot例 : 未適用 → 部分適用
- D1 1.4 ワークフロー強制 : 部分適用 → 適用済
```

**どのノウハウを、いつ、どの実装で身につけたか**が履歴として残る。

## 再計測の手順

1. 機能を実装し、コミットする（適用の「証拠」を作る）
2. 新しいチャットで、**前回ファイル**（`docs/arch-guide/` の最新 `ccaf-coverage-*.md`）を添付する
3. 「**CCAF適用率を出して**」と言う
4. 前回比つきの新しいレポート（`ccaf-coverage-YYYY-MM-DD.md`）が生成される
5. `docs/arch-guide/` に置いてコミット＆プッシュする

### コミット手順（Windows PowerShell）

```powershell
cd C:\Users\kazuy\projects\paper-repro

# 新しいレポートを docs/arch-guide/ に配置したあと
git status
git add docs/arch-guide/
git commit -m "docs: update CCAF coverage indicator YYYY-MM-DD"
git push
git log --oneline -1
```

## 再計測のタイミング（トリガー）

- ロードマップのフェーズが1つ完了したとき
- 大きな機能が入ったとき（構造化出力の導入、サンドボックス実装など）
- 節目でスライドや報告を作るとき

### 次に数値が動く見込み

現時点（2026-08-03）で **D4 プロンプト設計・構造化出力が 0.0%**。
フェーズ1で **tool_use + JSONスキーマによる論文情報の構造化抽出**を実装すると、
D4 が動き始め、総合適用率が上がる。

## 注意点

- **証拠のないものは「適用済」にしない。** 方針を文書に書いただけでは未適用として数える。
- **適用率を上げること自体を目的化しない。** 初期リリースに不要な型を入れるのは本末転倒で、
  採用しないものは「除外」と理由を書くのが正しい扱い。
- 過去のレポートファイルは**削除せず残す**（履歴として積み上げ、推移を追えるようにする）。
