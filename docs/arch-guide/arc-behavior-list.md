## 0. 本書の結論

確定済みのメイン要求11件とサブ要求12件を、**6業務グループ・47業務**へ割り当てた。
画面グループと番号を揃え、既存一覧にあった未確定IDの参照と存在しない状態値を除去した。

| 指標 | 値 |
| --- | --- |
| 業務グループ | 6 |
| システム化業務 | 47 |
| システム利用作業 | 25 |
| 機能 | 22 |
| 確定要求の対応 | 23 / 23 |
| 遷移型承認ゲート | 3 |
| 事象駆動承認ゲート | 3 |

本書は一覧としては**充実**である。ただし `REQ-C02`〜`REQ-C11` はUSDMの仕様粒度へ
未展開であるため、対応欄には確定要求IDを記し、存在しない仕様IDを作らない。

## 1. 記法と分類

### 1.1 業務グループ

| グループ | 名称 | 主な画面 | 主な工程 |
| --- | --- | --- | --- |
| 01 | プロジェクトとポートフォリオ | `S-01-01` | 全工程 |
| 02 | コース選択と切替 | `S-02-01` | `created`／全工程 |
| 03 | 取り込みと方針決定 | `S-03-01` | `created`／`intake_review` |
| 04 | 読解・学習・仕様化 | `S-04-01`／`S-04-02` | `reading` |
| 05 | 再現実装・検証・照合 | `S-05-01` | `implementing`／`scoring` |
| 06 | レポート・成果物・共有 | `S-06-01` | `scoring`／`done` |

### 1.2 列の意味

| 列 | 意味 |
| --- | --- |
| 種別 | `利用`＝人とシステムの相互作用、`機能`＝システムが自動実行する処理 |
| 分類 | `オンライン`、`非同期`、`イベント`、`手動判断`のいずれか |
| 利用者 | 初期リリースは単一の論文読解者。`system` は自動処理 |
| 状態 | `phase/status`。`*`は任意の工程、`—`は工程に依存しない |
| 要求／USDM | 確定要求ID。`REQ-C01`だけは展開済み仕様群も併記 |
| リリース | `初期`、`段階`、`将来`。要求を削除する意味ではない |

`course` は状態ではない。`reading`／`reproduction` は経路選択値として扱う。
