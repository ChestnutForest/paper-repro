## 1. ⚠️ 調査で判明した重大な事実

### 1.1 Papers with Code は終了している

**2025年7月に Meta が Papers with Code を終了した。** ドメインは Hugging Face の
Trending Papers へリダイレクトされ、リーダーボードは失われている。

`product-design.md` 201行は実装探索先に「PwC」を挙げているが、**この設計は現時点で成立しない。**

| 対応の選択肢 | 内容 |
| --- | --- |
| A | 実装探索を GitHub と OpenReview の2つに減らす |
| B | 代替サービス（CodeSOTA、凍結アーカイブ）へ差し替える |
| C | 初期リリースでは GitHub のみとし、他は後続で判断する |

**本書では決定しない。** 要求または設計の変更にあたるため、承認が要る（6章）。
一覧には `IF-03` として載せるが、**状態を「調査中止・要判断」とする。**

### 1.2 arXiv には謝辞の文言義務がある

利用条件として、次の文言を製品に表示することが求められている。

> Thank you to arXiv for use of its open access interoperability.

**これは画面編の対応が必要である**（フッタ等への表示）。`BR-08`（著作権・ライセンス）の
範囲だが、具体の表示箇所は未定である。

あわせて、**arXiv のブランド名・ロゴ・配色を製品に使わない**ことも求められている。

### 1.3 GitHub は認証の有無で83倍の差がある

| 認証 | 制限 |
| --- | --- |
| 未認証 | **60 リクエスト/時**（IPアドレス単位） |
| 個人アクセストークン | **5,000 リクエスト/時** |

実装探索は1論文あたり複数回の呼び出しを要するため、**未認証では実用に耐えない。**
認証を前提とする設計が必要である。

### 1.4 OpenReview は誤りが検出されない

**誤ったベースURL（v1/v2）を叩くと、エラーではなく空の結果が返る。**
また `invitation` 文字列は会議・年ごとに異なり、間違えても同様に空が返る。

**「結果ゼロ」を「該当なし」と解釈すると誤る。** `BR-10`（`unknown` を推測で埋めない）に
従い、**空の結果と取得失敗を区別する**必要がある。

## 4. インタフェースごとの制約

### 4.1 `IF-01` 論文メタ情報の取得（arXiv）

| 項目 | 内容 |
| --- | --- |
| レート制限 | **1リクエスト / 3秒**、同時接続は1本まで |
| 認証 | 不要 |
| メタデータのライセンス | CC0 1.0（パブリックドメイン） |
| **謝辞の文言** | **製品に表示する義務あり**（1.2節） |
| ブランド | arXiv の名称・ロゴ・配色を使わない |
| 既知の問題 | 制限内でも 429 が返る事例が報告されている（2026年2月〜） |

⚠️ **429 が返りうる前提で設計する。** 制限を守っていても失敗しうる。

### 4.2 `IF-02` 公式実装の探索（GitHub）

| 項目 | 内容 |
| --- | --- |
| レート制限 | 未認証 60/時、**認証 5,000/時** |
| 二次制限 | 同時接続100、REST 900ポイント/分 |
| 認証 | **必須とする**（1.3節） |
| 残量の確認 | `X-RateLimit-Remaining` ヘッダ、`/rate_limit` |

### 4.3 `IF-03` 公式実装の探索（Papers with Code）

⚠️ **サービスが終了している**（1.1節）。要判断。

### 4.4 `IF-04` 査読情報の取得（OpenReview）

| 項目 | 内容 |
| --- | --- |
| ベースURL | v2: `https://api2.openreview.net`（現行）／v1: `https://api.openreview.net`（レガシー） |
| 取得上限 | 1回あたり最大1,000件 |
| 認証 | ゲストアクセス可。トークンの有効期限は最大1週間 |
| **誤りの検出** | **誤ったURL・invitation でも空が返り、エラーにならない**（1.4節） |

⚠️ **空の結果と取得失敗を区別する。** `BR-10` に従う。

### 4.5 `IF-05` 文章生成の要求（LLM プロバイダ）

| 項目 | 内容 |
| --- | --- |
| 課金 | **従量課金**。上限の管理が必要 |
| 抽象化 | プロバイダ非依存の層で包む |
| 用途 | spec抽出、数式→コード下訳、翻訳 |
| 送信内容 | 論文本文の一部を含む。**著作権・機密の確認が要る** |

⚠️ **本インタフェースだけが従量課金である。** コスト上限の主対象となる。
