## 1. ⚠️ 調査で判明した重大な事実

### 1.1 Papers with Code は終了している（対応済み）

**2025年7月に Meta が Papers with Code を終了した。** ドメインは Hugging Face の
Trending Papers へリダイレクトされ、リーダーボードは失われている。

`product-design.md` 201行は実装探索先に「PwC」を挙げているが、**この設計は成立しない。**

✅ **2026年8月31日、Hugging Face Papers API への差し替えを決定した。**
経緯と根拠は [`../worknotes/decision-pwc-replacement.md`](../worknotes/decision-pwc-replacement.md) を参照。

**必要だったのは「論文と公式実装の紐付け」だけ**であり、リーダーボードや SOTA 追跡は
使っていなかった。Hugging Face Papers API は arXiv ID で直接引け、
GitHubリポジトリURLを返すため、この用途を満たす。

⚠️ **`product-design.md` 201行の修正は別途である。** 本書では外部IF側のみを更新した。

### 1.2 arXiv には謝辞の文言義務がある（対応済み）

利用条件として、**製品への**謝辞の表示が求められている。

✅ **2026年9月1日、文言と表示箇所を決定した。**
経緯と根拠は [`../worknotes/decision-arxiv-acknowledgement.md`](../worknotes/decision-arxiv-acknowledgement.md) を参照。

⚠️ **文言は2文である。** これまで記録していた第1文だけでは不足していた。

```
Thank you to arXiv for use of its open access interoperability.
This service was not reviewed or approved by, nor does it necessarily
express or reflect the policies or opinions of, arXiv.
```

第2文は「**arXiv の審査も承認も受けておらず、その見解を表すものでもない**」という否認である。
第1文だけでは arXiv が関与しているように読まれうる。

**表示箇所は全画面のフッタと、出力する成果物**とした。原文のまま表示し、翻訳しない。

**ロゴと名称はブランドとして使わない。** API利用だけでは通常ロゴ使用は許諾されず、
使わないことで独立プロジェクトの立場を保てる。

⚠️ **画面編（`arc-screen-rules.md`）へフッタの構成要素として追記が必要である。**

### 1.3 GitHub は認証の有無で83倍の差がある（対応済み）

| 認証 | 制限 |
| --- | --- |
| 未認証 | **60 リクエスト/時**（IPアドレス単位） |
| 個人アクセストークン | **5,000 リクエスト/時** |

実装探索は1論文あたり複数回の呼び出しを要するため、**未認証では実用に耐えない。**

✅ **2026年8月31日、fine-grained personal access token を必須とすることを決定した。**
経緯と根拠は [`../worknotes/decision-github-auth.md`](../worknotes/decision-github-auth.md) を参照。

**必要なのは公開リポジトリの読み取りだけ**であり、fine-grained PAT は既定でその権限を持つ。
classic PAT はアカウントの全リポジトリに及ぶため採らない。

⚠️ **トークンが無くても動作は止めない。** 未認証（60/時）で動くが、制限が低い旨を表示する。
初回利用の障壁を下げるための縮退動作であり、実用にはトークンが要る。

### 1.4 OpenReview は誤りが検出されない

**誤ったベースURL（v1/v2）を叩くと、エラーではなく空の結果が返る。**
また `invitation` 文字列は会議・年ごとに異なり、間違えても同様に空が返る。

**「結果ゼロ」を「該当なし」と解釈すると誤る。** `BR-10`（`unknown` を推測で埋めない）に
従い、**空の結果と取得失敗を区別する**必要がある。

## 4. インタフェースごとの制約

### 4.1 `IF-01` 論文メタ情報の取得（arXiv）

| 項目 | 内容 |
| --- | --- |
| レート制限 | **1リクエスト / 3秒**、同時接続は1本まで |
| 認証 | 不要 |
| メタデータのライセンス | CC0 1.0（パブリックドメイン） |
| **謝辞の文言** | **2文を製品に表示する**（1.2節）。原文のまま、翻訳しない |
| ブランド | arXiv の名称・ロゴ・配色を使わない |
| 既知の問題 | 制限内でも 429 が返る事例が報告されている（2026年2月〜） |
| **本文のライセンス** | ⚠️ **メタデータとは別である。** 大多数は arXiv の非独占配布許諾で、再利用の許可を伴わない |
| **本文の保存** | ✅ **可。** 個人利用または研究目的での取得・保存・利用は認められる |
| **本文の再配信** | ❌ **不可。** 自サーバから e-print（PDF・ソース等）を配信しない |
| 参照日 | 2026-09-09（[利用規約](https://info.arxiv.org/help/api/tou.html)） |

⚠️ **429 が返りうる前提で設計する。** 制限を守っていても失敗しうる。

#### 4.1.1 ⚠️ 本文の保存条件（2026年9月9日に確認）

**メタデータの CC0 1.0 は本文に及ばない。** 両者を混同しない。

| 対象 | ライセンス | 保存 | 再配信 |
| --- | --- | --- | --- |
| 記述メタデータ（題名、要旨、著者、識別子、分類） | CC0 1.0 | ✅ 可 | ✅ 可 |
| 本文（PDF・ソース・その他の内容） | **投稿者が選ぶ。大多数は arXiv 非独占配布許諾** | ✅ **個人利用・研究目的なら可** | ❌ **不可** |

⚠️ **「してよいこと」として明記されている。**
利用規約は「Retrieve, store, and use the **content** of arXiv e-prints for your own
personal use, or for research purposes」を許可している。

⚠️ **「してはいけないこと」も明記されている。**
「Store and serve arXiv e-prints from your servers」は、
著作権者の許可か投稿時のライセンスによる許諾がない限り禁じられる。
**再配布を許すライセンスで投稿された e-print はごく一部である。**

**設計への影響。**

| 論点 | 判断 |
| --- | --- |
| 本文をローカルに保持してよいか | ✅ **よい。** 単一利用者の個人利用にあたる |
| 保存期間の上限 | **規約上の制限はない。** 物理設計で決める |
| 保存場所 | 利用者の管理下。`REQ-C09-S01.160`（特定の端末でしか開けない形式で保存しない）と両立する |
| 成果物へ本文を含めてよいか | ❌ **含めない。** 共有・公開すると再配信にあたる |
| 本文を LLM へ送ってよいか | ⚠️ **`IF-05` の権利確認が要る**（[`interfaces/IF-05.md`](interfaces/IF-05.md)）。送信は再配信と別だが、送信先の学習利用の有無を確認する |

⚠️ **`REQ-C09-S03`（公開範囲の選択）と `REQ-C09-S05`（外部照会）は、
本文そのものを外部へ出さない設計にする。** 引用の範囲に留める。

### 4.2 `IF-02` 公式実装の探索（GitHub）

| 項目 | 内容 |
| --- | --- |
| レート制限 | 未認証 60/時、**認証 5,000/時** |
| 二次制限 | 同時接続100、REST 900ポイント/分 |
| **認証方式** | **fine-grained personal access token**（1.3節） |
| **権限** | **公開リポジトリの読み取りのみ**（既定） |

⚠️ **期限切れは 401 で返る。** GitHub の障害と誤って表示しない。再発行を促す（`BR-07`）。

## 4.5 ⚠️ 要求の再検査（2026年9月8日）

⚠️ **本書は全要求の網羅を宣言していない。** 第0章のとおり、本書は
[`../product-design.md`](../product-design.md) に書かれた外部サービスを

**要求33件のうち27件が本書に現れないのは漏れではなく、外部との接点を持たないためである。**

新設7要求のうち、外部との接点を持ちうる3件を個別に判定した。

| 要求 | 外部との接点 | 判定 |
| --- | --- | --- |
| `REQ-C09-S05` 外部照会の記録と返礼 | 論文著者その他への照会の送信 | ⚠️ **`IF-06`（成果物の外部送信）の隣接。判定が要る** |
| `REQ-C07-S03` 公開議論由来の情報 | 公開の場の議論の取得、利用規約に反する自動収集の禁止 | ⚠️ **新しい接続先が要るかの判定が要る** |
| `REQ-C12` 再現スコープの定義 | なし | ✅ **接点なし。** 論文から抽出した情報を整理するだけである |

### 4.5.1 `REQ-C09-S05` の判定

要求文は「照会の送信は利用者の明示的な操作によるものとし、システムが自動的に外部へ
照会を送信しないものとする」と定める。仕様 `REQ-C09-S05.40`・`.50` が同じ内容である。

⚠️ **`IF-06` は「初期リリース対象外」として接続先が未定である**（第5章の項目5）。
`product-design.md` 261行も「外部送信は初期リリースで実装しない」としている。

- **担当工程**：外部インタフェース編の設計
- **解除条件**：`IF-06` の接続先が定まること。照会の送信が `IF-06` に含まれるか、
  別のインタフェース（`IF-07`）として立てるかを、**送信手段（メール、フォーム、API）が決まってから**判断する
- **再判断の期限**：`IF-06` の接続先を決める時点
- **状況**：照会は初期リリースの範囲だが、送信手段は未定である。
  ⚠️ **要求は初期リリース、インタフェースは対象外という不一致がある**

### 4.5.2 `REQ-C07-S03` の判定

要求文は「特定の外部サービスが利用不能になった場合でも、取得済みの記録を参照できる」
「利用規約に反する自動収集を行わない」と定める。仕様 `REQ-C07-S03.100`〜`.120` が対応する。

⚠️ **`REQ-C07-S03.120` が「自動収集を行わない場合の取得手段（利用者による貼り付け等）を用意する」
と定めている。** 貼り付けは外部インタフェースではない。

- **担当工程**：外部インタフェース編の設計
- **解除条件**：公開議論の取得を自動収集で行うか、利用者の貼り付けに限るかが定まること。
  **自動収集を採らないなら、新しいインタフェースは不要である**
- **再判断の期限**：`arc-screen-list.md` 5.3節（`F-19`）の解除時
- **状況**：`IF-04`（査読情報の取得、OpenReview）が既にあり、
  **公開議論の一部はここで賄える可能性がある**
