# CCAF適用率 算定規則とテンプレート

paper-repro の開発工程が、CCAR-F 試験ガイドのノウハウをどこまで適用しているかを
**計測・可視化**するための規則と、出力ファイルのテンプレート。

---

## 1. 算定規則

### 単位

CCAFのタスクステートメント1本を1単位とする（全30本）。

| ドメイン | 内容 | 本数 | 配点 |
|---|---|---|---|
| D1 | Agentic Architecture & Orchestration | 7（1.1〜1.7） | 27% |
| D2 | Tool Design & MCP Integration | 5（2.1〜2.5） | 18% |
| D3 | Claude Code Configuration & Workflows | 6（3.1〜3.6） | 20% |
| D4 | Prompt Engineering & Structured Output | 6（4.1〜4.6） | 20% |
| D5 | Context Management & Reliability | 6（5.1〜5.6） | 15% |
| 計 | | 30 | 100% |

### 状態の3値

| 状態 | 点 | 判定基準 |
|---|---|---|
| **適用済** | 1.0 | そのタスクの型が、実装・設定・運用として**実在する**。証拠を示せる |
| **部分適用** | 0.5 | 一部だけ実現している、または限定的な形で使っている。証拠を示せる |
| **未適用** | 0 | 実在しない。**方針を文書に書いただけは未適用**（意図は実装ではない） |

### 計算式

```
ドメイン適用率 = そのドメインの点数合計 ÷ そのドメインの本数
総合適用率     = Σ（ドメイン適用率 × ドメイン配点）
```

例：D3が2.5/6=41.7%なら、総合への寄与は 0.417 × 0.20 = 8.3ポイント。

### バーグラフの作り方

20マスで表す。`█` = 塗り、`░` = 空き。マス数 = round(適用率 × 20)。

---

## 2. 証拠の書き方（最重要）

**「適用済」「部分適用」には必ず証拠を1つ以上添える。** 証拠として認めるもの：

- ファイルパス（例：`backend/app/core/states.py`）
- コミットID（例：`733a359`）
- devlogの日付と項目（例：`devlog-2026-07-27.md 決定ログ`）

**証拠が出せないものは未適用にする。** 設計文書に「そうする方針」と書いてあるだけでは適用済にしない。
実装・設定・運用実績が存在して初めて適用済とする。

### 除外（初期リリーススコープ外）の扱い

意図的に採用しないものは、**未適用のまま**にし、備考に除外理由を書く。
適用率を上げるために不要な型を入れるのは本末転倒なので、除外理由を明示することの方が価値がある。

```markdown
## 次に適用率を上げるなら（優先順）

配点 × 未適用度で効果の大きい順に、次に着手すべきタスクを挙げる。
ただし**ロードマップのフェーズ順を無視してまで適用率を追わない**こと。

| 優先 | タスク | 見込み上昇 | 対応フェーズ |
|---|---|---|---|

## 計測の前提（この数値の読み方）

- 単位はタスクステートメント1本、3値評価（適用済1.0／部分適用0.5／未適用0）
- 総合＝Σ（ドメイン適用率×配点）
- **証拠のないものは未適用として数えている**（方針の記述のみは含めない）
- 初期リリーススコープ外の型は未適用のままとし、除外理由を備考に記載
```

## 4. 再計測のタイミング

- ロードマップのフェーズが1つ完了したとき
- 大きな機能が入ったとき（例：構造化出力の導入、サンドボックス実装）
- 節目でスライドや報告を作るとき

再計測時は、**前回ファイルが会話にある場合のみ**前回比を書く。無ければ「初回計測」と明記する（捏造しない）。
