## 1. 原則：一覧が先である

**どの編でも、まず「一覧」を作る。** 詳細はその後に書く。

| 編 | 最初に作る成果物 | ガイドが定める役割 |
| --- | --- | --- |
| 画面編 | 画面一覧 | 画面の全体、概要を示す |
| システム振舞い編 | システム化業務一覧 | **目次としての役割を担う** |
| データモデル編 | エンティティ一覧 | 対象データの目次 |
| （今後の3編） | 各編の一覧に相当するもの | 同様 |

### 1.1 「目次」の意味

REF-16 は、システム化業務一覧の役割を**目次**と定義している。

これは「何があるかを列挙するもの」であり、**それ自体は詳細を持たない**という意味である。
本の目次が章題だけを並べ、中身は各章に譲るのと同じ構造をとる。

| 成果物 | 役割 | 本にたとえると |
| --- | --- | --- |
| 一覧 | 何があるかを列挙 | **目次** |
| フロー・遷移 | それらがどう繋がるか | 章の構成図 |
| 説明・レイアウト | 各項目の中身 | 各章の本文 |
| 共通ルール | 全体に共通の約束 | 凡例・表記規則 |

**一覧以外の成果物は、一覧に載った項目について書くものである。**

## 2. 順序が逆だと何が起きるか

一覧を作らずに詳細から始めると、次の3つが起きる。

### 2.1 完了を判定できない

「これを描いて、次にあれを描いて」と進めても、**どこで止めればよいかが分からない。**
全部描けたのか、漏れがあるのかを判定する基準が無い。

一覧があれば「20項目のうち15描いた」と数えられる。
[`../traceability-matrix.md`](../traceability-matrix.md) の進捗管理も、
一覧の行数を分母として成り立つ。

### 2.2 粒度が揃わない

一覧を作る過程で、**項目を区切る基準**が確定する。

| 編 | 区切りの基準 |
| --- | --- |
| 画面編 | 利用者から見た機能のまとまり |
| システム振舞い編 | **場所・時間・作業者**（[`arc-behavior.md`](arc-behavior.md) 3.3節） |

基準が無いまま詳細を書くと、ある箇所は細かく、別の箇所は粗くなる。
**後から揃え直すには、書いたものを全部見直すことになる。**

### 2.3 IDを後付けすることになる

`S-nn-mm`（画面）や `B-nn-mmm`（システム化業務）は、**一覧で採番する。**

詳細を先に書くと、後からIDを振り直し、図も文書も書き直すことになる。
[`arc-screen.md`](arc-screen.md) 第4章と [`arc-behavior.md`](arc-behavior.md) 第4章が
ID体系を先に定めているのは、この手戻りを避けるためである。

---

## 3. ⚠️ 実際にこの失敗をしている

[`arc-behavior.md`](arc-behavior.md) の v0.1 は、**状態遷移を最優先の成果物**としていた。
理由は「実装が先行していて設計文書が無いから」であった。

しかし v0.2 で、**状態遷移はガイドの工程成果物ではない**ことが判明した
（[`../worknotes/reflection-arc-behavior-v02.md`](../worknotes/reflection-arc-behavior-v02.md)）。

一覧を作らないまま状態遷移から始めていたら、次のようになったはずである。

| 起きたこと | 結果 |
| --- | --- |
| 状態は定義できる | しかし**どの業務がその状態で動くのか**対応づけられない |
| 後から一覧を作る | 状態遷移と粒度が合わない |
| 両方を書き直す | 手戻り |

**この失敗は、順序を独自に決めたことから生じた。**
ガイドが定める順序には理由がある。

## 4. 例外：共通ルールは一覧と同時に作る

**共通ルールだけは、最後に回さない。**

| 編 | 共通ルール |
| --- | --- |
| 画面編 | 画面遷移・レイアウト共通ルール |
| システム振舞い編 | システム振舞い共通ルール |
| データモデル編 | データモデル共通ルール・レビュー基準 |

後回しにすると、**個別の項目ごとに表記や配色を決めてしまい、後から揃え直せなくなる。**
配色を10画面に散らばせてから統一するのは、最初に決めるより遥かに高くつく。

### 4.1 実際の作成順序

```
[1] 一覧  ＋  [4] 共通ルール     ← 同時に着手
       ↓
[2] フロー・遷移
       ↓
[3] 説明・レイアウト
```

番号は各編における工程成果物の番号ではなく、**作成の順序**を示す。

## 6. 一覧を作る前に決めること

一覧の作成に着手する前に、次の2つを確定させる。

| 決めること | 参照先 |
| --- | --- |
| **ID体系**（採番の規則） | 各編の第4章 |
| **区切りの基準**（何を1項目とするか） | 各編の該当節 |

**これらが未定のまま一覧を書き始めると、途中で採番をやり直すことになる。**

---

## 7. やってはいけないこと

- ❌ 一覧を作らずに詳細（フロー、レイアウト、説明）から書き始める
- ❌ 共通ルールを最後に回す
- ❌ ID体系を決めずに一覧を書き始める
- ❌ **ガイドの成果物でないものを最優先に据える**（3章の失敗）
- ❌ 一覧に無い項目を、先に詳細から起こす
