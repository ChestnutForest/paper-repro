# IF-01 論文メタ情報の取得

## 書誌情報

| 項目 | 内容 |
| --- | --- |
| 外部IF-ID | `IF-01` |
| 名称 | 論文メタ情報の取得 |
| 接続先 | `EX-01` arXiv |
| 方向 | 入力（取得） |
| 対応業務 | `B-03-001`（論文の入手元を指定する）ほか |
| 対応要求 | `REQ-C03`、`REQ-C03-S01` |
| 公式ドキュメント | https://info.arxiv.org/help/api/ （2026-08-31 参照） |
| 版 | v0.1（2026年9月1日） |

⚠️ **本インタフェースが止まると取り込みそのものができない。** 依存度が最も高い
（[`../arc-interface-map.md`](../arc-interface-map.md) 2章）。

## 1. 項目説明

### 1.1 送信する項目

| 階層 | 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- | --- |
| 1 | `id_list` | 文字列 | ○ | arXiv識別子。`2404.08335v1` の形式 |
| 1 | `max_results` | 整数 | — | 取得件数。1件取得のため既定は1 |

⚠️ **利用者が入力するのはURLである。** そこから識別子を取り出して送る。
版指定（`v1`、`v2`）を落とさない。`BR-04` が論文版の区別を求めるため。

### 1.2 受信する項目

応答は Atom 形式である。JSON ではない。

| 階層 | 項目名 | 型 | 説明 |
| --- | --- | --- | --- |
| 1 | `entry` | 要素 | 論文1件。0件なら該当なし |
| 2 | `id` | 文字列 | 正規化されたarXiv URL。**版を含む** |
| 2 | `updated` | 日時 | 最終更新日時 |
| 2 | `published` | 日時 | 初版の公開日時 |
| 2 | `title` | 文字列 | 論文題名 |
| 2 | `summary` | 文字列 | Abstract |
| 2 | `author` | 要素の繰り返し | 著者。0件以上 |
| 3 | `author/name` | 文字列 | 著者名 |
| 2 | `category` | 要素の繰り返し | 分野。`cs.CL` などの形式 |
| 2 | `link` | 要素の繰り返し | 関連URL。PDF・abstract・DOI |
| 2 | `arxiv:comment` | 文字列 | 著者による注記。**採択情報を含むことがある** |
| 2 | `arxiv:journal_ref` | 文字列 | 掲載誌情報。無い場合が多い |
| 2 | `arxiv:doi` | 文字列 | DOI。無い場合が多い |

**全体レコード長・可変長固定長区別**: `—`（Atom形式のため該当しない）

### 1.3 ⚠️ 項目の欠落を許す

`arxiv:comment`、`arxiv:journal_ref`、`arxiv:doi` は**存在しないことが多い。**
欠落を異常として扱わず、`unknown` として保持する（`BR-10`）。

⚠️ **`arxiv:comment` から採択情報を推測しない。** 「Accepted at NeurIPS 2024」と
書かれていても、著者の自己申告である。査読情報は `IF-04` が扱う。

## 2. 処理説明

### 2.1 接続の条件

| 項目 | 内容 |
| --- | --- |
| 接続先 | `http://export.arxiv.org/api/query` |
| 認証 | 不要 |
| レート制限 | **1リクエスト / 3秒**、同時接続1本 |
| データ量 | 1件あたり数KB |
| 保存期間 | メタデータは CC0 1.0。制限なし |
| 保存場所 | `Paper` エンティティ（[`../arc-datamodel-definitions.md`](../arc-datamodel-definitions.md)） |

### 2.2 事前条件

- 利用者が arXiv URL を入力し、識別子を取り出せている。
- 前回の呼び出しから **3秒以上経過**している。
- 同時に別の arXiv 呼び出しが実行中でない。

### 2.3 本処理

1. 識別子を `id_list` に指定して要求を送る。
2. 応答を Atom として解析する。
3. `entry` が1件あれば、1.2 の項目を取り出す。
4. 取得元・取得日時・対象版を伴わせて保存する（`BR-02`）。

### 2.4 終了条件

| 結果 | 状態 | 次の動作 |
| --- | --- | --- |
| `entry` が1件 | 成功 | 取り込みを続ける |
| `entry` が0件 | **該当なし** | 識別子の誤りを利用者へ伝える |
| `429` | 一時的な失敗 | `BR-13` に従い再試行 |
| 接続不能 | 一時的な失敗 | 同上 |

### 2.5 ⚠️ 制限を守っても 429 が返る

2026年2月以降、**3秒間隔を守っていても 429 が返る事例**が報告されている。

**制限内の失敗を異常終了として扱わない**（`BR-13`）。再試行の対象とする。

### 2.6 ⚠️ 謝辞の表示義務

arXiv は製品への謝辞の表示を求めている。**2文を原文のまま表示する。**
詳細は [`../arc-screen-rules.md`](../arc-screen-rules.md) `CR-12`。

**ロゴ・配色・名称をブランドとして使わない。**

### 2.7 代替手段

本インタフェースが使えない場合、**利用者による手入力**で代替できる。
題名・著者・Abstract を手で入れて取り込みを続けられるようにする。

⚠️ **手入力した値は、取得元を「利用者入力」として記録する**（`BR-10`）。
arXiv から取得した値と混同しない。
