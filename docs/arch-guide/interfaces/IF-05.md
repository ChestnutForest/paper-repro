# IF-05 文章生成の要求

## 書誌情報

| 項目 | 内容 |
| --- | --- |
| 外部IF-ID | `IF-05` |
| 名称 | 文章生成の要求 |
| 接続先 | `EX-05` LLM プロバイダ |
| 方向 | **出力・入力**（送信と取得の両方） |
| 対応業務 | 未特定（一覧 3.3節） |
| 対応要求 | `REQ-C04`、`REQ-C05` |
| 用途 | spec抽出、数式→コード下訳、翻訳 |
| 版 | v0.1（2026年9月1日） |

⚠️ **本インタフェースだけが従量課金である。** コスト上限の管理対象は
ここに限られる（`BR-13`）。

⚠️ **本インタフェースだけが双方向である。** 論文本文を送り、生成結果を受け取る。
**送信する内容の権利確認が要る。**

---

## 1. 項目説明

### 1.1 ⚠️ 具体的なプロバイダを書かない

[`../../product-design.md`](../../product-design.md) は「抽象化層で包む」
「他プロバイダ差替可」「プロバイダ非依存に」と定める。

**本書は抽象化層の入出力を記述する。** 特定プロバイダの項目名を書くと、
差し替え時に本書を書き直すことになる。

### 1.2 送信する項目（抽象化層）

| 階層 | 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- | --- |
| 1 | `task` | 列挙 | ○ | `spec_extract` / `code_draft` / `translate` |
| 1 | `source_text` | 文字列 | ○ | **論文本文の一部**。全文ではない |
| 1 | `source_ref` | オブジェクト | ○ | 送信箇所の由来 |
| 2 | `source_ref/paper_id` | 文字列 | ○ | 対象論文 |
| 2 | `source_ref/version` | 文字列 | ○ | 論文版（`BR-04`） |
| 2 | `source_ref/location` | 文字列 | ○ | 節・数式番号など |
| 1 | `instruction` | 文字列 | ○ | 指示文 |
| 1 | `max_tokens` | 整数 | — | 上限 |

⚠️ **`source_ref` を必須とした。** `BR-10` は情報源・版・位置の追跡を求める。
何を送ったか分からない生成結果は、由来を辿れない。

### 1.3 受信する項目（抽象化層）

| 階層 | 項目名 | 型 | 説明 |
| --- | --- | --- | --- |
| 1 | `output_text` | 文字列 | 生成結果 |
| 1 | `model` | 文字列 | **使用したモデル識別子** |
| 1 | `usage` | オブジェクト | 消費量 |
| 2 | `usage/input_tokens` | 整数 | 入力トークン数 |
| 2 | `usage/output_tokens` | 整数 | 出力トークン数 |
| 1 | `finish_reason` | 文字列 | 終了理由。`length` なら**途中で切れた** |

**全体レコード長・可変長固定長区別**: `—`（JSON のため該当しない）

### 1.4 ⚠️ `model` を必ず記録する

`BR-10` は「モデル、プロンプト、利用者訂正を追跡可能にする」と定める。

**同じ入力でもモデルが違えば結果が変わる。** どのモデルが生成したか分からなければ、
後から再現も検証もできない。

### 1.5 ⚠️ `finish_reason` が `length` の場合

**生成が途中で切れている。** 完全な結果として扱わない。

途中で切れた spec を確定させると、欠落したまま実装へ進む。
**切れたことを利用者へ明示する**（`BR-07`）。

## 2. 処理説明

### 2.1 接続の条件

| 項目 | 内容 |
| --- | --- |
| 接続先 | 抽象化層が解決する。本書では特定しない |
| 認証 | **必要**。環境変数から読む |
| 課金 | **従量**。トークン数に応じる |
| レート制限 | プロバイダ依存 |
| タイムアウト | **他より長くとる**。生成に時間がかかるため（`BR-13`） |
| データ量 | 入力は論文の一部、出力は数KB |
| 保存期間 | 生成結果は成果物として保存。**送信内容も記録する** |

### 2.2 事前条件

- 認証情報が環境変数から読める。
- **コスト上限に達していない**（`BR-13`）。
- 送信する本文の**権利上の制約を確認済み**である。
- 送信箇所の `source_ref` を組み立てられている。

### 2.3 ⚠️ 送信前の権利確認

**論文本文を外部へ送る。** `BR-08` と `BR-11` が関わる。

| 確認 | 内容 |
| --- | --- |
| 著作権 | 論文のライセンスが外部送信を許すか |
| 送信範囲 | **全文を送らない。** 必要な箇所に限る |
| 機密 | 利用者の注記に個人情報が混じっていないか |

⚠️ **`BR-11` は「外部送信はプレビューと権利・機密確認後の明示操作に限る」と定める。**
本インタフェースは外部送信にあたる。

### 2.4 本処理

1. コスト上限の残量を確認する。
2. 送信内容と `source_ref` を組み立てる。
3. 要求を送る。
4. 応答から `output_text`・`model`・`usage` を取り出す。
5. **消費量を記録し、累計へ加算する**（`BR-13`）。
6. 生成結果を**未検証の候補**として保存する（`BR-06`）。

### 2.5 終了条件

| 結果 | 状態 | 次の動作 |
| --- | --- | --- |
| 成功・`finish_reason` が正常 | 成功 | 未検証の候補として保存 |
| 成功・`finish_reason` が `length` | **途中で切れた** | 不完全である旨を表示 |
| `401` | 認証失敗 | 再試行しない。設定を促す |
| `429` | 一時的な失敗 | `BR-13` に従い再試行 |
| タイムアウト | 一時的な失敗 | 同上 |
| コスト上限到達 | **停止** | 新規呼び出しを止める（2.6節） |

### 2.6 ⚠️ コスト上限に達したとき

`BR-13` に従う。

| 対象 | 挙動 |
| --- | --- |
| 新規の `IF-05` 呼び出し | **止める** |
| **実行中のジョブ** | **完了まで進める** |
| `IF-01`〜`IF-04` の取得 | 続けられる |
| 利用者の手作業 | 続けられる |

**実行中を止めない理由**は、中断すると途中までの生成結果が残り、
`BR-11`（失敗で成果物を削除しない）の趣旨に反する中途半端な状態になるためである。

### 2.7 ⚠️ 生成結果を承認済み判断として保存しない

`BR-06` は「LLM出力は機能の結果であり、承認済み判断として保存しない」と定める。

**生成された spec や下訳は、利用者が確認するまで候補である。**
承認ゲート（`BR-09`）を経て初めて確定する。

### 2.8 代替手段

**利用者による手作業**で代替できる。spec を手で書き、数式を自分でコードへ落とす。

⚠️ **手作業の結果は、生成結果と区別して記録する**（`BR-10`）。
どちらが由来かで、後の検証の重みが変わる。
