## 1. 項目説明

### 1.1 送信する項目

| 階層 | 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- | --- |
| 1 | `invitation` | 文字列 | ○ | 会議・年ごとに異なる。**壊れやすい** |
| 1 | `content.title` | 文字列 | — | 論文題名で照合する場合 |
| 1 | `limit` | 整数 | — | 取得件数。**最大1,000** |
| 1 | `offset` | 整数 | — | 取得開始位置 |

⚠️ **`invitation` の文字列は会議ごとに異なる。** `ICLR.cc/2024/Conference/-/Submission`
のような形式で、年や会議が変われば変わる。**推測で組み立てない。**

### 1.2 受信する項目

| 階層 | 項目名 | 型 | 説明 |
| --- | --- | --- | --- |
| 1 | `notes` | 配列 | 論文または査読。0件以上 |
| 2 | `id` | 文字列 | OpenReview内の識別子 |
| 2 | `forum` | 文字列 | 議論スレッドの識別子 |
| 2 | `invitation` | 文字列 | 種別 |
| 2 | `content` | オブジェクト | 内容。**会議ごとに構造が違う** |
| 3 | `content/title` | 文字列 | 題名 |
| 3 | `content/rating` | 文字列 | 評点。**無い場合がある** |
| 3 | `content/confidence` | 文字列 | 査読者の確信度。無い場合がある |
| 3 | `content/decision` | 文字列 | 採否。無い場合がある |
| 2 | `cdate` | 数値 | 作成日時（ミリ秒） |

**全体レコード長・可変長固定長区別**: `—`（JSON のため該当しない）

### 1.3 ⚠️ `content` の構造は会議ごとに違う

同じ `rating` でも、会議によって尺度が異なる（1〜10、1〜5 など）。
**数値だけを取り出して比較しない。** 尺度を伴わせて保存する。

### 1.4 ⚠️ 査読情報で論文の正しさを判定しない

`BR-08` は「査読、引用数だけで真偽や不正を確定しない」と定める。
**査読情報は参考であり、判断の根拠にしない。**

## 2. 処理説明

### 2.1 接続の条件

| 項目 | 内容 |
| --- | --- |
| 接続先 | **`https://api2.openreview.net`**（v2・現行） |
| 旧接続先 | `https://api.openreview.net`（v1・レガシー） |
| 認証 | 任意。ゲストアクセス可 |
| トークン | 使う場合は**有効期限が最大1週間** |
| 取得上限 | 1回あたり最大1,000件 |
| データ量 | 査読1件あたり数KB |
| 保存期間 | 制限なし。ただし引用条件を保存する |

### 2.2 事前条件

- 対象論文が特定済みである。
- **ベースURLが v2 である**ことを確認済み。
- `invitation` の文字列が実在するものである。

### 2.3 本処理

1. `invitation` を指定して要求を送る。
2. 応答の `notes` を解析する。
3. **`notes` が0件の場合、2.5 の判定を行う。**
4. 取得元・取得日時を伴わせて保存する（`BR-02`）。

### 2.4 終了条件

| 結果 | 状態 | 次の動作 |
| --- | --- | --- |
| `notes` が1件以上 | 成功 | 査読情報として保存 |
| `notes` が0件 | **判定が必要**（2.5節） | — |
| 接続不能 | 一時的な失敗 | `BR-13` に従い再試行 |

### 2.5 ⚠️ 空の結果が失敗を隠す

**本インタフェース最大の注意点である。**

誤ったベースURL（v1/v2）や誤った `invitation` を送っても、
**エラーではなく空の結果が返る。**

| 原因 | 応答 |
| --- | --- |
| 該当する査読が無い | `notes` が0件 |
| **ベースURLが誤り** | **`notes` が0件** |
| **`invitation` が誤り** | **`notes` が0件** |

**「空 = 該当なし」と解釈すると、設定誤りに気づけない。**

#### 判定の手順

1. ベースURLが v2 であることを確認する。
2. `invitation` が実在するか、別の要求で確かめる。
3. 両方が正しければ「該当なし」とする。
4. 確認できなければ **`unknown`** とし、判定を利用者へ委ねる（`BR-13`）。

### 2.6 代替手段

**無い。** 査読情報は OpenReview 以外から得にくい。

ただし影響度は低く、**査読情報を欠いたまま工程を進められる。**
その場合、欠落していることを画面に明示する（`BR-13`）。
