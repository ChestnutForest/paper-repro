## 1. 変更概要

現行要件の「着手可能な再現実装まで到達させる伴走型パイプライン」を維持しながら、
製品価値を次の二つの同等な経路へ拡張する。

1. **読解・学習経路**: 原論文の理論、数式、モデル構造を理解し、演習と自己説明を通じて独力で読む力を育てる。
2. **再現実装経路**: 公式実装読解、コード生成、隔離実行、サニティチェック、論文値照合まで行う。

最終的には、多言語コード対応、主張単位の証拠台帳、完全プロヴェナンスグラフ、論文ポートフォリオを
提供する。ただし、初期リリースのPython・タイプB・縦切り方針は維持し、ロードマップ上で段階的に拡張する。

## 2. 変更理由

- 「はじめに」は、原論文から理論的基礎を理解し、独力で読み解く能力と継続学習を重視している。
- 現行要件は再現実装、安全な実行、再現性、コスト管理に強い一方、対象利用者、学習到達点、演習、根拠比較、継続学習が不足している。
- 実装方法自体は書籍の主題ではないが、理論理解のために公式実装を読むことが不可欠とされており、読解と再現実装は対立せず相互補完できる。
- 利用者は、初学者支援、拡張性、多言語対応、矛盾を隠さない証拠比較、詳細監査、長期学習を最終的な製品価値として選択した。
- 「1.2.2」は、成立条件、実験設定、具体例・反例、公式実装、重要参考文献、自己説明を一つの読解過程として扱う必要性を示している。
- 「1.2.2.1」は、前提と帰結の分離、読解深度の線引き、実験条件の公平性、不確実性、
  省略された議論の自力検証を、`REQ-C10`の独立した三つの検証工程として詳細化している。
- 「1.2.2.2」は、操作可能な具体例、計算過程、支持例・反例・境界条件、予想と観察結果、
  仮説と検証済み結論の区分を、`REQ-C04-S01`と`REQ-C10-S03`の要件として詳細化している。
- 「1.2.2.3」は、論文箇所と版付き公式実装の双方向対応、差異分類、入手可能性、検査可能性、
  人間による採用根拠を、`REQ-C05-S01`の要件として詳細化している。
- 「1.2.2.4」は、重要文献、データセット、関連実装の優先付け、深掘り、探索状態、
  時点付き参考信号を、`REQ-C09-S02`の要件として詳細化している。

## 6. 維持する要求

次の現行要求は一次資料や選択結果と矛盾せず、製品固有の重要な強みとして維持する。

- 各Phase末のhuman-in-the-loopと承認履歴
- 信頼できないコードのホスト直接実行禁止
- ネットワーク、CPU、メモリ、時間、書込量、ファイルシステムの制限
- シークレット分離とログへの秘密情報出力禁止
- サニティ階段、論文値照合、再現性、冪等・再開性
- LLM・実行コストの事前見積もりと予算上限
- 論文の主張自体の学術的真偽判定をスコープ外とする境界
- 公開モデルの網羅的カタログを提供しない方針
- 初期リリースをタイプB・公式実装あり・CPU中心で縦切りする方針

## 14. 推奨する変更順序

1. 本変更案について、利用者が承認、修正または保留を判断する。
2. 具体化済みの12件のサブ要求候補を確認し、残る`REQ-C02-S01`と`REQ-C08-S01`を
   後続小節の詳細分析で具体化する。
3. `requirements.md`へ承認された要求、追加ID、維持事項、保留事項を反映する。
4. `product-design.md`で画面、状態遷移、API、データモデル、承認境界を設計する。
5. `roadmap.md`で初期縦切りと最終到達点を分離し、特に次を段階化する。
   - `REQ-C08:1 → 2 → 3 → 4`
   - `REQ-C09:1 → 2 → 3 → 4`
   - `REQ-C11:1 → 2 → 3 → 4`
   - Python実行 → C/C++静的読解 → 言語アダプタ → 言語別サンドボックス
6. 設計確定後に`tech-stack.md`を更新する。
7. データモデルと移行計画を作り、段階間の後方互換性を確認する。
8. 受入基準を自動テスト・セキュリティテスト・人間の確認手順へ割り当てる。
9. 初期リリースの縦切りを崩さず、ロードマップ順に実装する。
