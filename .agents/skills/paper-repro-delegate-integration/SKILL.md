# Claude Code への統合依頼

## 1. いつ使うか

claude.ai のチャットで文書の一部（章・節）を作成し、それをリポジトリ内の既存文書へ
統合する必要があるとき。

**特に次の条件が1つでも当てはまるなら、PowerShell で編集せず本手順を使う。**

- 挿入によって既存の章番号・節番号がずれる
- 複数箇所の参照（「第N章」など）を同時に直す必要がある
- 挿入と削除を同じファイルに対して行う
- 変更が10箇所を超える

### 1.1 なぜ委譲するのか

PowerShell で行の配列と文字列を混ぜて操作すると、改行コードが壊れる。

```powershell
# ❌ これをやってはいけない
$t = [IO.File]::ReadAllText($p)
[IO.File]::WriteAllLines($p, $t.Split([char]10), (New-Object Text.UTF8Encoding $false))
```

CRLF を含むファイルを LF で分割すると各行末に `\r` が残り、`WriteAllLines` が
そこへさらに改行を付ける。**全行の間に空行が入り、225行の文書が865行になる。**

2026年9月3日に実際に発生し、`git checkout` で作業ごと差し戻した。

## 2. 手順

### 2.1 素材を作る

claude.ai 側で、挿入する内容だけを含むファイルを作り、利用者がダウンロードする。

- **挿入する本文だけを書く。** 前後の既存内容を含めない
- 測定用の覚え書き（実測値の表など）を末尾に付けた場合は、依頼文で除外を指示する

### 2.2 素材を配置する

```powershell
Copy-Item -Path "$env:USERPROFILE\Downloads\<素材名>.md" -Destination .\<素材名>.md -Force; Test-Path .\<素材名>.md
```

リポジトリのルートへ一時的に置く。統合後に削除する。

### 2.3 依頼文を組み立てる

**次の5項目を、この順で書く。** 不要な項目は飛ばしてよいが、順序は変えない。

```
<素材名>.md を <対象ファイル> へ統合して。

1. 内容を、現在の「<挿入位置の見出し>」の直前へ新しい第N章として挿入する。
2. 既存の「<見出し>」を「## N+1.」へ、「<見出し>」を「## N+2.」へ繰り下げる。
3. この文書自身の章を指す「第M章」への参照を「第M+1章」へ直す。
   <他文書を指す参照がある場合はその除外を明記する>
4. 新しいN+1章の節番号を <旧> から <新> へ直し、<元の記述の削除内容>。
5. <一覧・冒頭の記述の更新内容>。

改行コードは LF、BOM なしを維持すること。

完了したら「終わりました！」と表示すること。
```

#### 各項目の注意

**2番の繰り下げ。** 番号の大きいほうから指示する。小さいほうから直すと、
その結果を次の置換が拾って二重にずれる。

**3番の参照。** 同じ「第N章」でも、**この文書自身を指すものと他文書を指すものがある。**
`requirements-usdm.md` には `requirements.md` 第8章を指す記述があり、繰り下げの対象外である。
**除外を明記しないと、正しい参照まで書き換わる。**

**4番の削除。** 元の記述が「節ごと削除」か「表の1行だけ削除」かを区別する。
表に複数の要求が並んでいる場合、節ごと消すと他の要求まで失う。

**5番の一覧。** 「加える」のか「削除する」のかを明確に書く。
4番の内容と混ざりやすい。

### 2.4 統合結果を検証する

**必ず3つとも実行する。**

```powershell
Select-String -Path <対象ファイル> -Pattern "^#{2,3} " | Format-Table LineNumber,Line -AutoSize
```

章と節の番号が連番になっているか。挿入した章が意図した位置にあるか。

```powershell
git --no-pager diff --stat
```

⚠️ **差分の規模が最も重要な検査である。**
素材の行数に近い追加なら正常。**数倍になっていたら改行コードが壊れている。**

| 状態 | 差分の例 |
|---|---|
| 正常 | 211行追加・9行削除 |
| 異常 | 452行追加・285行削除（素材は180行） |

```powershell
git grep -n "<修正した参照>" -- <対象ファイル>
```

参照が意図どおり直っているか。他文書を指す参照が巻き込まれていないか。

### 2.5 素材を削除してコミットする

```powershell
Remove-Item .\<素材名>.md; git status --short
```

対象ファイルの変更だけが残ることを確認する。

```powershell
git add -A; git commit -m "<型>: <要約>

<本文2〜3文>"
```

**コミットは作業の区切りごとに行う。** 要求1件の展開、選択1件の記録、
正本の変更、下流の追随はそれぞれ別の区切りとする。

⚠️ **統合が済んだら、次の作業に入る前にコミットする。**
未コミットのまま次の編集を始めると、事故が起きたとき両方を失う。

### 2.6 push と確認URL

```powershell
git push; powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\validate-agent-skills.ps1' -RequireRemoteSync; git status --short
```

確認URLは `paper-repro-commit-output` の規則に従い、1 URL ずつ独立した
`text` コードブロックへ入れる。

## 3. 異常時の対応

### 3.1 差分の規模が異常なとき

**編集を続けず、直ちに差し戻す。**

```powershell
git checkout -- <対象ファイル>; git status --short
```

`git status` が空になれば、直前のコミットの状態へ戻る。
**素材ファイルは削除しない。** 差し戻し後に再統合するため。

### 3.2 依頼が部分的にしか実行されなかったとき

5項目のうち一部が漏れることがある。2.4節の検証で検出する。

漏れた項目だけを、あらためて依頼する。**全体をやり直さない。**

## 4. この手順を使わない場合

次の編集は PowerShell で行ってよい。

- 1箇所の文字列置換（`WriteAllText` を使う）
- 表への1行の追加
- 版数や日付の更新

```powershell
$p="<パス>"; $t=[IO.File]::ReadAllText($p); $old='<旧>'; $new='<新>'; if($t.Contains($old)){[IO.File]::WriteAllText($p,$t.Replace($old,$new),(New-Object Text.UTF8Encoding $false)); 'replaced'}else{'NOT FOUND'}
```

**末尾に `replaced` / `NOT FOUND` を返させる。** 置換が効いたかを毎回確認する。

⚠️ **`WriteAllText` と `ReadAllText` の組で統一する。**
`WriteAllLines` を使う場合は `ReadAllLines` で読んだ配列だけを渡す。
**両者を混ぜない。**
